# p1 topic: string key catalog (i18n and i18n-aniyomi, base English)

Generated by reading every `base` XML file in scope. Columns: `#`, module, kind (`string` or `plurals`), key as written in XML, `translatable` (XML attribute), English base value (plurals show each quantity), Kotlin/Android references found by a repo-wide scan, and status.

Reference legend: `MRxN` = N occurrences of `MR.strings.<key>` or `MR.plurals.<key>` in `.kt` files; `AYMRxN` = same for `AYMR`; `R.xN` = legacy `R.string.<key>` or `R.plurals.<key>` (Android-generated resource class, used by notification and widget code); `xml xN` = `@string/` or `@plurals/` reference in an Android `res` XML. Dotted keys are referenced with underscores (for example `action.addExtensionStore` is `action_addExtensionStore` in Kotlin, and the core `extensionStoresScreen.*` keys are referenced as `extensionStoresScreen_*`).

Status `no direct reference found` means no literal `MR.`/`AYMR.`/`R.` reference was found by grep. Moko accessors are generated, so the key is only dead if no dynamic lookup exists. Verify before deleting.
