# 51-i18n: Rust design

All code below is PROPOSAL. Kotlin behaviour cited is OBSERVED. Background: [p1-topic-xml-to-fluent.md](p1-topic-xml-to-fluent.md) (conversion), [p1-topic-locale-and-display-names.md](p1-topic-locale-and-display-names.md) (locales).

## 1. Crates

| Need | Crate | Why | Version policy |
|---|---|---|---|
| Message formatting with named args, plural selection | `fluent-bundle` (with its `concurrent` module) | Named placeholders, CLDR plural categories per language, translator-friendly syntax, `NUMBER()` for `%d`/`%02d`/`%.2f` | latest stable at implementation, pinned in `Cargo.lock` |
| Language identifiers | `unic-langid` | Used by `fluent-bundle`; parses and canonicalises BCP 47 tags | same |
| Date formatting, localised short dates and month names | `icu_datetime` (ICU4X) | Locale-correct short dates and `MMM` names; chrono cannot do this | same |
| Native and English language names (generated once) | `icu_displaynames` (ICU4X), used by an offline generator only | Produces the committed table in the locale topic file. Not a runtime dependency | dev-only |
| Build-time XML parsing for the converter | `quick-xml` (in `xtask` only) | Robust parsing of moko XML, including `translatable` attributes and entities | dev-only |
| System locale list | `glib::language_names()` (already in `gtk4` / `glib`) | GLib implements the `LANGUAGE`/`LC_ALL`/`LC_MESSAGES`/`LANG` order | none, already present |
| Embedding the `.ftl` files | `include_str!` through a build script (`build.rs`) | No extra crate | none |

Not used: `gettext-rs` (needs libintl and has no named args), `rust-i18n` (YAML/JSON, weaker plural support), `sys-locale` (GLib already gives the list), `moko` (Android/Kotlin only).

`Cargo.toml` additions (proposal, versions to be resolved by cargo):

```toml
[dependencies]
fluent-bundle = { version = "*", features = ["concurrent"] }   # resolve to latest stable
unic-langid = "*"
icu_datetime = "*"

[build-dependencies]
# none for embedding; build.rs uses std only

[workspace]
members = [".", "xtask"]

# xtask/Cargo.toml
[dependencies]
quick-xml = "*"
fluent-syntax = "*"       # only to validate generated .ftl at import time
```

Edition stays `2024` as in the mockup `Cargo.toml`. Note: in edition 2024 `std::env::set_var` is `unsafe`; see section 7.

## 2. Module layout

Inside the existing mockup crate (`/home/blackbox/kurobayomi`, package `kurobayomi`):

```
src/i18n/mod.rs          public API: tr(), tr_plural(), set_language(), current_locale()
src/i18n/keys.rs         GENERATED by build.rs: enum MsgKey, const MSG_COUNT
src/i18n/catalog.rs      load embedded .ftl, build bundles, lookup + fallback chain
src/i18n/locale.rs       tag normalisation, startup resolution, RTL flag
src/i18n/names.rs        native/english display names table (committed data)
src/i18n/time.rs         relative time and short-date helpers built on the catalog
src/i18n/data.rs         generated: LOCALES: &[(&str, &str, &str)] (tag, ftl text, rtl)
xtask/src/main.rs        subcommands: i18n-import, i18n-check, i18n-keys
xtask/src/i18n_import.rs moko XML -> Fluent conversion (section 8)
locales/<tag>/kurobayomi.ftl   generated translation files (committed)
locales/en/kurobayomi.ftl      generated English source (committed)
build.rs                 generates src/i18n/keys.rs and src/i18n/data.rs from locales/
```

`build.rs` (proposal) reads `locales/en/kurobayomi.ftl`, extracts message ids in file order, writes `MsgKey` and the table of `(tag, text, rtl)` for every directory in `locales/`. Cargo re-runs it when `locales/` changes (`cargo:rerun-if-changed=locales`).

## 3. Key types and signatures

```rust
// src/i18n/keys.rs  (GENERATED)
#[derive(Clone, Copy, Debug, PartialEq, Eq, Hash)]
#[allow(non_camel_case_types)]
pub enum MsgKey {
    action_cancel,
    action_ok,
    // ... one variant per message id in locales/en/kurobayomi.ftl (1,434 total)
    relative_time,
    // ...
}

impl MsgKey {
    pub const fn id(self) -> &'static str { /* match arm per variant */ }
}
```

Variant names are the Fluent ids unchanged, so a typo fails to compile. Enum variants that start with a digit do not occur (ids start with a letter by the converter's rule).

```rust
// src/i18n/mod.rs
use fluent_bundle::FluentValue;

/// Argument value. Use Str for %s, Int for %d, Dec for %.Nf.
pub enum Arg<'a> {
    Str(&'a str),
    Int(i64),
    Dec(f64),
}

/// Plain message (<string>), no arguments.
pub fn tr(key: MsgKey) -> String;

/// Message with named arguments. Names are the Fluent variable names (arg1, arg2 ...).
pub fn trf(key: MsgKey, args: &[(&str, Arg<'_>)]) -> String;

/// Plural message (<plurals>). `count` selects the CLDR category, and is also
/// available to the pattern as $count. Extra args are $arg1, $arg2 ...
pub fn tr_plural(key: MsgKey, count: i64, args: &[(&str, Arg<'_>)]) -> String;

/// Set the active language for subsequent calls. Called once at startup; a later call
/// is ignored with a warning (no live switch, see section 4).
pub fn init(requested: Option<&str>);

pub fn current_locale() -> &'static LocaleInfo;
```

The API forbids passing a count that disagrees with `arg2` for `notification_chapters_multiple_and_more` and `notification_episodes_multiple_and_more`: the two wrappers `tr_notification_multiple_and_more(remaining, joined)` build both values from one `remaining`.

Wrapper for the Java `%d` and `%02d` cases:

```rust
pub fn fmt_hms_minutes_seconds(minutes: u32, seconds: u32) -> String {
    trf(MsgKey::restore_duration, &[
        ("arg1", Arg::Int(minutes as i64)),
        ("arg2", Arg::Int(seconds as i64)),
    ])
}
```

Catalog internals:

```rust
// src/i18n/catalog.rs
use fluent_bundle::concurrent::FluentBundle;
use fluent_bundle::FluentResource;
use unic_langid::LanguageIdentifier;
use std::sync::OnceLock;

pub struct Catalog {
    bundles: Vec<(LanguageIdentifier, FluentBundle<FluentResource>)>, // requested chain order
    english: FluentBundle<FluentResource>,
}

static CATALOG: OnceLock<Catalog> = OnceLock::new();

impl Catalog {
    /// Build bundles for the requested chain, e.g. ["pt-BR", "pt", "en"].
    /// Missing translations fall through to the English bundle at lookup time.
    pub fn build(chain: &[LanguageIdentifier]) -> Catalog;

    /// Returns formatted text. Falls back down the chain, then to the id itself.
    pub fn format(&self, id: &str, args: Option<&fluent_bundle::FluentArgs>) -> String;
}
```

`fluent_bundle::concurrent::FluentBundle` is `Send + Sync`, which permits `OnceLock`. Each bundle must call `set_use_isolating(false)` right after construction.

Lookup algorithm (PROPOSAL, exact):

1. Walk the bundle chain in order. For each bundle, if `has_message(id)` and the message has a value, call `format_pattern`.
2. If no bundle in the chain has the id, log `warn!("missing message {id}")` once (a `HashSet<&str>` guarded by a `Mutex`) and return `id`.
3. Collect the Fluent errors vector. Log it at `debug` and still return the formatted text. Never panic.

Overlap rule (topic file section 6): the Aniyomi overlap keys are generated from the Aniyomi source only, so no extra branch is needed at runtime.

## 4. Startup and language change

```rust
// src/i18n/locale.rs
pub struct LocaleInfo {
    pub tag: &'static str,
    pub native_name: &'static str,
    pub english_name: &'static str,
    pub rtl: bool,
}

/// Resolution order: pref `app_language` (non-empty) → glib::language_names() → "en".
pub fn resolve(pref_app_language: &str) -> Vec<unic_langid::LanguageIdentifier>;

/// Normalise one tag (topic file section 5). Returns None for unparsable input.
pub fn normalise(raw: &str) -> Option<unic_langid::LanguageIdentifier>;
```

Startup sequence (proposal, `src/main.rs`):

1. Load preferences (area:02). Read `app_language` only (plain file read, no GTK needed).
2. `i18n::init(Some(pref))` (or `None` if empty). This builds the chain and the catalog. It does not call GTK.
3. `gtk::Application::builder()…build()`, then `app.connect_startup` sets the text direction from `current_locale().rtl` with `gtk::Widget::set_default_direction` (GTK 4.16 API, the mockup uses `v4_16`).
4. Build windows. All `tr()` calls happen after step 2.

Runtime language change: writes `app_language` only. The running app keeps the old language. A restart note is shown (behaviour §9.6, UI parity §2).

## 5. Threading model

- GTK main loop: all widget text is built here. `tr()` calls here are fine.
- tokio runtime: background work (library update, downloads, backups) runs on tokio worker threads. Those threads must NOT build user-visible text. They send a typed message to the GTK side:

```rust
pub enum UiMsg {
    Notify { key: MsgKey, args: Vec<OwnedArg> },   // formatted on the main thread
    Toast { key: MsgKey, args: Vec<OwnedArg> },
}

pub enum OwnedArg { Str(String), Int(i64), Dec(f64) }
```

- The main thread drains the channel (`glib::MainContext::channel` or `async_channel` + `glib::spawn_future_local`) and calls `trf` / `tr_plural` there. Notification bodies therefore use the language active at the time of display.
- `OnceLock<Catalog>` is thread-safe, so `tr()` also works from any thread. The rule above is about consistency and avoiding GTK calls off the main thread, not about the catalog being unsafe.

## 6. Error handling

```rust
#[derive(Debug, thiserror::Error)]   // or a hand-written enum if thiserror is not already a dependency
pub enum I18nError {
    #[error("bad locale file {tag}: {message}")]
    BadLocale { tag: String, message: String },
    #[error("placeholder mismatch in {tag}/{id}: expected {expected:?}, got {got:?}")]
    PlaceholderMismatch { tag: String, id: String, expected: Vec<String>, got: Vec<String> },
}
```

- `BadLocale` at import time (`xtask`) is a hard error for the whole locale (the locale is dropped from the build, with a warning). It is never raised at runtime.
- Runtime parse errors (should not happen, since `xtask` validates) are logged and the English message is used.
- Placeholder mismatch: import-time error per message; the message falls back to English in that locale.

Logging: `tracing` is not used by the mockup (`Cargo.toml` has only gtk, serde, serde_json). PROPOSAL: use `eprintln!` with a `[i18n]` prefix until the logging area decides; the `log` facade is an alternative (owned by area:01).

## 7. Environment and GTK details

- `glib::language_names()` returns the list in priority order. Only the first match is used by the chain builder.
- Edition 2024: `std::env::set_var` is `unsafe`. This design never calls it: language selection is in-process (the catalog), not via environment variables. GTK itself reads `LANGUAGE`/`LC_*` at its own init for its built-in dialogs (file chooser, etc.); the app does not change those. Accept that GTK's own dialogs follow the system language. Document it in the UI parity file.
- Text direction: `gtk::Widget::set_default_direction(TextDirection::Rtl | Ltr)` is process-wide and must be called before the widgets are created.

## 8. Converter (xtask) design

`xtask/src/i18n_import.rs` (PROPOSAL). Inputs: the four base XML files and each locale's two XML files. Outputs: `locales/<tag>/kurobayomi.ftl`.

```rust
pub struct Source {
    pub module: Module,             // Core | Aniyomi
    pub id: String,                 // moko name with '.' -> '_'
    pub kind: Kind,                 // Plain(String) | Plural(Vec<(Quantity, String)>)
    pub translatable: bool,
}

pub enum Quantity { Zero, One, Two, Few, Many, Other }

pub fn parse_moko(xml: &str, module: Module) -> Result<Vec<Source>, ParseError>;
pub fn to_fluent(src: &Source, placeholders_base: &[PlaceholderRef]) -> Result<String, ConvertError>;
pub fn check_placeholders(base: &[PlaceholderRef], tr: &[PlaceholderRef]) -> Result<(), I18nError>;
```

Import steps:

1. Parse all base files. Build the English table with the overlap rule (Aniyomi wins). Write `locales/en/kurobayomi.ftl`.
2. For each locale directory (skip empty files): parse the two files, convert, check placeholders against the English entry for the same id. Failures: fall back to English for that id and print a warning line to stdout (no report file is written).
3. Validate every output file with `fluent_syntax::parser::parse` (`Err((res, errs))` → fail import).
4. Write `build.rs` input table.

Key rename: `.` → `_`. Duplicate detection after rename: two distinct source keys mapping to one id is a hard error (none exists in the current base files; test covers it).

## 10. Pitfalls

1. Fluent isolation marks: forgetting `set_use_isolating(false)` puts invisible U+2068/U+2069 characters into labels. GTK shows some fonts as boxes.
2. Plural categories: Fluent needs `*[other]`. The converter must always emit it. A missing default is a parse error at runtime.
3. Shared string state: `OnceLock<Catalog>` is initialised once. Calling `init` a second time must not rebuild (ignore or return an error). Live switching is out of scope.
4. GTK widgets keep the text they were built with. A translation change does not repaint them.
5. Mixed direction text: GTK labels with mixed RTL and LTR text need `set_xalign` and the bidi algorithm handled by Pango; do not use manual `‏` marks.
6. `%c` in `player_gesture_seek_indicator`: the caller must pass one character as a `Str`. Passing a longer string is valid for Fluent but changes the layout.
7. `remaining` duplication for the two multiple-and-more messages: never pass different values.
8. Escaping in Rust: do not write `\n` into `.ftl` by hand; use the converter output (`{"\u000A"}`).
9. Sorting by native name uses Unicode code point order (`str::cmp`), not locale collation. Accept and document.
10. ICU4X data size: `icu_datetime` with compiled data adds binary size. Use the `compiled_data` default and check binary size after the first build.

## 11. Integration with the mockup

Current state (OBSERVED): the mockup has no i18n layer. It contains about 756 quoted string literals in `src/*.rs`, of which many are UI labels (`src/entry.rs` 270, `src/screens.rs` 204, `src/settings.rs` 107, `src/player.rs` 101, `src/ui.rs` 39, `src/main.rs` 30, `src/clamp.rs` 1, `src/spec.rs` 4). The spec files (`spec/*.json`) hold English text directly, and `spec/SCHEMA.md` says the strings must be the real English text from the Aniyomi `strings.xml` files.

Proposal:
- `spec/*.json`: every `title`, `subtitle`, `options` text becomes a key (`"title_key": "pref_category_appearance"`). Keep the English text only in the Fluent English file. The `spec.rs` loader (`src/spec.rs:121-137`, which calls `include_str!` on four files and `serde_json::from_str`) gains a resolver `fn text(key: &str) -> String` that calls `i18n::tr` through a `MsgKey` lookup by string (`MsgKey::from_id(&str) -> Option<MsgKey>`, generated).
- `src/ui.rs` `heading(text: &str)` and similar helpers keep taking `&str`. Callers pass `tr(MsgKey::…)`.
- Spec `"options": [str]` arrays become arrays of keys. Values stored in preferences stay the same English-independent identifiers (for example `"update_weekly"`), never the translated text.
- A test in `spec.rs` (existing `spec_is_consistent`) extends to: every key in the spec exists in `MsgKey`.

Migration order: (1) `i18n` module plus generated keys; (2) convert `spec/*.json` keys; (3) convert `src/` literals screen by screen (owned by the UI areas).
