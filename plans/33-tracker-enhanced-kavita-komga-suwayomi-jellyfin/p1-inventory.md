## Per-file notes that change the port

1. **Jellyfin.kt and Komga.kt declare an explicit DNS policy.** Each one overrides `dns(Dns.SYSTEM)` with the comment "don't use DNS over HTTPS as it breaks IP addressing" (`Jellyfin.kt:31`, `Komga.kt:30`). The same is true for `KavitaApi.kt:26`, `SuwayomiApi.kt:32`. Rust: all four trackers use the system resolver (reqwest default). See T-33a-004.
2. **Kavita is inconsistent about DNS.** `KavitaApi.getNewToken` uses the constructor `client`, which is `BaseTracker.client` (`networkService.client`, DoH-enabled). Every other Kavita call uses `authClient`, which is `Dns.SYSTEM`. The port uses system DNS everywhere (observed defect D-04 in `p1-behavior.md`).
3. **Komga has no interceptor and sends no Authorization header.** `Komga.kt:28-31` builds a client with only `dns(Dns.SYSTEM)`. `KomgaApi.kt:28-32` adds only `User-Agent`. Authentication therefore depends on cookies in the shared `AndroidCookieJar` (`core/common/src/main/java/eu/kanade/tachiyomi/network/NetworkHelper.kt:18`, `:22`). This is an open design question (see `p1-rust-design.md` section 10).
4. **Suwayomi reads its server settings lazily and only once per process.** `SuwayomiApi.kt:45-47` (`baseUrl`, `baseLogin`, `basePassword`) are `by lazy`, and `Suwayomi.kt:20` creates `api` lazily. Changing the server address after first use is not picked up until restart (observed defect D-08).
5. **Interceptor-based auth becomes explicit functions.** `KavitaInterceptor.kt`, `JellyfinInterceptor.kt` and the header code in `KomgaApi.kt:28-32` and `SuwayomiApi.kt:35-43` add headers by side effect. In Rust, each request is built by a function that receives an explicit `AuthContext`. Nothing hides behind a chain.
6. **No Compose, Activity, dialog, or menu code exists in this scope.** The `p1-ui-parity.md` file is therefore omitted. The only UI-facing values in scope are the logo resource ids (`R.drawable.ic_tracker_*`, `Color.rgb(...)`) and the string keys listed in `p1-behavior.md` section 7. The UI itself lives in `app/src/main/java/eu/kanade/presentation/more/settings/screen/SettingsTrackingScreen.kt`, which belongs to area:27-tracking-core.
7. **No upstream `*Test.kt` file exists inside the scope.** The only upstream test references are in the Kavita server repository (`Kavita.Services.Tests/TachiyomiServiceTests.cs`, read-only research). See `p1-edge-cases-and-tests.md`.
