## 2. Edge cases and failure modes

| ID | Situation | OBSERVED behaviour | Rust requirement |
|---|---|---|---|
| EC-01 | `getMangaById`/`getAnimeById` for a missing id; `...AsFlow` when the row is deleted while collected | `awaitOne` throws; `subscribeToOne` flow fails (SQLDelight `executeAsOne`/`mapToOne` on zero rows) | `by_id` returns `Err(DataError::NotFound)`; `subscribe_by_id` emits `None` after deletion; UI closes the details page. Test T-05a-005. |
| EC-02 | Duplicate check with non-ASCII capitals (`"Éclair"`, `"ДОКТОР"`) | Kotlin `lowercase()` is Unicode, SQLite `LOWER()` is ASCII-only: no match | Fixed with `lower_unicode` on both sides (T-05a-019); test that `"Éclair"` finds `"éCLAIR"`; and that ASCII behaviour is unchanged. |
| EC-03 | Upcoming list across midnight | `getUpcoming*` computes `startOfDay` once at call time | Recompute per re-query and schedule a midnight refresh (T-05a-020); test with an injected clock. |
| EC-04 | `updateManga(title only)` | Trigger `update_last_favorite_at_*` fires because the SET list names `favorite`: `favorite_modified_at` changes on every update | Preserved (static statement). Test: update only `title`, assert `favorite_modified_at` is non-NULL afterwards and `last_modified_at` is within 2 s of `now_secs()`. |
| EC-05 | Description changes between NULL and text | `new.description != old.description` is NULL so `version` is NOT bumped; text->different text bumps by 1 | Preserved. Tests: NULL->"a" (no bump), "a"->"b" (+1), "a"->"a" (0), url change (+1), favorite change (+1), title change (0). |
| EC-06 | `setCategories(id, [a,b,c])` | version +3 (one per link insert), delete does not bump | Preserved. Test with 0, 1, 3 ids. |
| EC-07 | `addAllChapters` failure (for example NOT NULL violation in the 50th element) | whole transaction rolled back, logged, returns `emptyList()`; `SyncChaptersWithSource` has already deleted removed chapters in a separate transaction, so new chapters are lost silently | Rust returns `Err`; the legacy adapter maps to empty list for the interactor. Test: a failing element leaves the table unchanged. Recommendation recorded for area:10-app-domain-layer: run remove+add+update in one transaction. |
| EC-08 | No unique index on `(manga_id, url)` of chapters, `(anime_id, url)` of episodes, `(source, url)` of mangas/animes | duplicates can be inserted (two concurrent syncs, or `NetworkToLocal` race) | Do not add indexes here (area:03-db-manga-schema-migrations and area:04-db-anime-schema-migrations own schema; adding a UNIQUE index would make restore of old backups fail). Document; `by_url_and_source` uses `LIMIT 1` as in SQL. Test that two inserts of the same (url, source) both succeed at repository level. |
| EC-09 | `getChapterByUrlAndMangaId` with duplicates | `executeAsOneOrNull` throws on 2+ rows | Return smallest `_id`, `tracing::warn!` (T-05a-008). |
| EC-10 | Category order after delete | system row renumbered to 0, user categories to 1..n; a following reorder gives the first user category 0 as well (tie with system row) | `ORDER BY sort, _id` (T-05a-010); test sequence: create A,B,C -> delete B -> orders {system 0, A 1, C 2}; reorder C to index 0 -> {system 0, C 0, A 1}; `all()` returns system, C, A. |
| EC-11 | Manga category deletion cleanup | `library_update_categories_exclude` is not cleaned (copy-paste bug), anime version is correct | Fixed in Rust (T-05a-025); test: delete category 5 while ids "5" in both include and exclude sets: both sets lose "5". |
| EC-12 | Duplicate rows in `excluded_scanlators` (the table has no key) | `getChaptersByMangaId` with the filter flag 0 still LEFT JOINs the table, so each duplicate `(manga_id, scanlator)` row repeats the matching chapters in the result; with the flag 1 matching chapters are removed entirely so nothing repeats | The only writer, `SetExcludedScanlators` (app/src/main/java/eu/kanade/domain/entries/manga/interactor/SetExcludedScanlators.kt, inside one transaction: read current set, insert only `toAdd = new - current`, delete `toRemove = current - new`), never creates duplicates. Rust `ChapterRepo::set_excluded_scanlators` (T-05a-021) must follow the same diff algorithm. The chapter SQL stays identical; a test documents the multiplication when a duplicate is inserted by hand so a future change is deliberate. |
| EC-13 | Library view row multiplicity | one row per (entry, category link); an entry in 3 categories counts 3 times in naive `len()` | `LibraryManga` consumers group by `category`; provide helper `library_by_category(rows) -> BTreeMap<i64, Vec<&LibraryManga>>` ordered by category `order` (the join to `categories.sort` is done in the UI). Test with an entry in 0 and 3 categories. |
| EC-14 | Relation fetches create non-favorite anime rows (up to groups x 10 per fetch) | never cleaned automatically | Not changed; surfaced in the clear-database screen via `getDeletableParentAnime`. |
| EC-15 | Season with zero episodes inside a Seasons parent | counted as fully seen (0 = 0) | Preserved; test with a parent whose children have totals {0, 5/5, 5/3}: `seenCount` = 2 (the empty one and the complete one). |
| EC-16 | `fetch_type` outside {0,1} | view stats NULL, Kotlin mapper crashes | Rust reads NULL stats as 0; test inserting `fetch_type = 7`. |
| EC-17 | `IN` list sizes | SQLDelight expands directly (1000+ ids can exceed Android's 999 limit) | chunk 500, one transaction; test removing 1 200 chapters. |
| EC-18 | Corrupt `memo` JSON | `SerializationException` fails the entire list query | Fall back to `{}` with warning; test with BLOB `not json`. |
| EC-19 | Genre containing `", "` | splits into two genres on read | Preserved; test round-trip `["Action, Adventure"]` yields `["Action","Adventure"]`. |
| EC-20 | Second process holds a lock (user opens the DB with `sqlite3` while the app runs, or two app instances) | Kotlin: a single process; SQLITE_BUSY is possible but rare on Android | Proposal: `PRAGMA busy_timeout = 5000` on both connections; `SingleInstance` (kuro-platform) prevents two instances. Test: hold an exclusive lock on another connection for 1 s, assert the write succeeds. |
| EC-21 | Row id reuse | `_id INTEGER PRIMARY KEY` without AUTOINCREMENT reuses the largest freed id: deleting manga 90 and inserting a new one can yield 90 again | Preserved. Consequence: any cache keyed by id (cover cache, in-memory UI state) must be invalidated on delete. Test documents it. |
| EC-22 | `setCategories` with a nonexistent category id | FK violation -> exception -> transaction rolled back; old links preserved | Same; test asserts old links are intact after a failing call. |
| EC-23 | `deleteCategory(0)` | trigger aborts with "System category can't be deleted" | Same; test the exact message in `DataError::Sqlite`. |
| EC-24 | Entry deleted while subscribed lists exist | cascades chapters; chapter-list flows are not notified by SQLDelight because cascades are untracked | Superset notifier (T-05a-002); test that a chapter-list subscription emits an empty list. |
| EC-25 | Timestamp unit confusion | seconds for `last_modified_at`/`favorite_modified_at`, milliseconds elsewhere | Distinct constructor names `now_secs()`/`now_millis()`; test that after an update `last_modified_at < 10_000_000_000` (seconds-scale) and `date_fetch > 10_000_000_000`. |
| EC-26 | Concurrent writes from two tasks (chapter sync and mark-read) | SQLDelight serialises transactions on the dispatcher | Single writer connection serialises automatically; test with 20 concurrent `update_all` tasks, assert final state and no `SQLITE_BUSY`. |
| EC-27 | Updating a row that does not exist | 0 rows changed, reported as success (`true`) | Preserved (no error). Test. |
| EC-28 | `updateAllAnime([])` | opens an empty transaction, returns true | Preserved; Rust may skip the transaction. Test returns Ok. |
| EC-29 | `reset_viewer_flags` | every row's `viewer = 0`, including anime skip-intro bits | Not exposed for anime in the UI (no Kotlin caller). Test on manga only; anime test asserts the data-loss so nobody wires it casually. |
| EC-30 | `hidden` values other than 0/1 | `hidden == 1L` only | Preserved: test value 2 reads as visible. |
| EC-31 | Sanitizer outputs an empty name | name equals manga title | Stored as `""`; the UI shows a fallback (area:38-ui-entry-details-manga and area:39-ui-entry-details-anime). Test vector in `p1-topic-item-sanitizer.md`. |
| EC-32 | Disk full or read-only database | Kotlin returns `false`/empty list via swallowed errors; UI shows generic toasts | Rust returns `DataError::Sqlite(SQLITE_FULL / READONLY)`; app-level handler (area:01-foundation-app-bootstrap) shows one dialog and keeps the app read-only. Test with a read-only connection: `update` returns Err and nothing panics. |
| EC-33 | Opening a database newer than the app (higher `user_version`) | not handled in this scope (area:03-db-manga-schema-migrations and area:04-db-anime-schema-migrations) | `Db::open` must refuse with a clear error; test with `PRAGMA user_version = 9999`. |

## 3. Test plan

Harness (T-05a-023): `kuro-core/tests/support/mod.rs` provides `Db::open_in_memory(kind)` which runs the DDL of area:03-db-manga-schema-migrations and area:04-db-anime-schema-migrations (their `schema_manga.sql`/`schema_anime.sql` produced by the migration code, not copied by hand), builders `MangaBuilder::new().title("x").favorite(true).insert(&repo)`, `ChapterBuilder`, `EpisodeBuilder`, `CategoryBuilder`, a clock abstraction (`trait Clock { fn now_millis(&self) -> i64; fn start_of_day_millis(&self) -> i64 }`) injected into the upcoming queries, and a helper `assert_sorted_by_id` for unsorted queries. Run with `cargo test -p kuro-core`; no GTK, no network, runs under 5 s.
