# Area 07 — topic: upstream quirks (Q) and design decisions (D)

Every row is OBSERVED behaviour of the Kotlin in scope (or its direct callers) that a Rust port must either preserve or deliberately change. "Policy" = what Kurobayomi does. Policy summary: preserve anything that is persisted or compared across syncs/backups (numbers, flag bits, preference keys); fix anything that can crash or that is pure waste; every deviation has a test in T-07a-041.

## Quirks

| Id | Where | Observed behaviour | Impact | Policy |
|---|---|---|---|---|
| Q1 | `ShouldUpdateDbChapter.kt:7-13`, `ShouldUpdateDbEpisode.kt:7-17` with `SyncChaptersWithSource.kt:107-141` | A source that reports `dateUpload = 0` makes `db.dateUpload != source.dateUpload` true on every refresh (the DB row holds `now` stored at first insert); the row is added to `updatedChapters` although the update keeps the old `dateUpload` (`if (chapter.dateUpload != 0L)`), so each refresh writes identical data and calls `awaitUpdateLastUpdate` | `lastUpdate` is bumped on every refresh of such entries; fetch-interval prediction and "Latest update" sorting are polluted; a no-op DB transaction per entry | FIX (deviation D4): in the Rust `should_update_db_*`, ignore the `date_upload` comparison when the source value is 0. ## Decisions

| Id | Decision | Reason |
|---|---|---|
| D1 | Recognition regexes: `regex` crate with consuming rewrite of look-behind/look-ahead (p1-topic-item-number-recognition.md 4); `fancy-regex` only if a vector fails | no extra dependency; linear-time matching; all 57 upstream vectors verified with the rewrite |
| D2 | `chrono` (feature `clock`) for local-day arithmetic in fetch interval; epoch-ms `i64` at module boundaries; reconcile with area:05-data-repos-entries-items `time` helpers | DST-correct zone rules via OS; generic `TimeZone` makes UTC tests trivial |
| D3 | `icu_collator` (ICU4X) PRIMARY strength for alphabetical item/season sorts | closest to Android's ICU `Collator`; no C library |
| D4 | Behavioural fixes limited to Q1, Q2, Q8, Q13, Q16, Q17, Q20, Q21; everything else bug-for-bug | stored data and backups depend on stable numbers; each fix has a regression test |
| D5 | No repository traits in the domain layer; domain functions take `&MangaRepo`/`&AnimeRepo`/`&ChapterRepo`/`&EpisodeRepo` (area:05-data-repos-entries-items concrete types). Tests use the in-memory SQLite harness (area:05-data-repos-entries-items T-05a-023) | one implementation each; a trait would be pure ceremony. If an in-memory fake is ever needed it can be added behind the same method names |
| D6 | The Kotlin "interactor per verb" classes become free functions or inherent methods grouped per file (`queries.rs`, `flag_setters.rs`, `default_flags.rs`); dependency injection is replaced by passing `&AppContext` (area:01-foundation-app-bootstrap T-01a-003) or the specific repo | classes exist only for Injekt |
| D7 | Flags are `i64` words with `const` masks and typed accessors, never `bitflags!` | multi-bit enumerated groups; exact stored values are a file-format contract |
| D8 | Error policy: pure functions never panic on bad data; repository errors surface as `Result`; the facade functions that Kotlin wrapped in try/catch (`GetChapter`, `GetChaptersByMangaId`, `GetEpisode*`, `UpdateChapter`, `UpdateEpisode`, `GetAnimeSeasonsByParentId`) keep their "log and return None/empty/unit" contract under names ending `_or_none` / `_or_empty` / `_logged`, so call sites do not accidentally gain new failure modes | preserves UI behaviour |
| D9 | `Instant.now()`/`ZonedDateTime.now()` calls become an injected `Clock` (`fn now_ms(&self) -> i64`, `fn zone(&self)`) | deterministic tests |
