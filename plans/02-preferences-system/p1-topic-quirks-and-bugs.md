# Topic: quirks and bugs found in the preference code, with the Kurobayomi decision for each

Each entry gives OBSERVED behaviour (with `path:line`), the user-visible impact, and the decision. "Keep" means the Kotlin behaviour is reproduced on the wire (key strings, stored values) so Aniyomi backups keep working. "Fix" means Kurobayomi deviates internally but still writes compatible data.

| Q1 | `domain/src/main/java/tachiyomi/domain/library/service/LibraryPreferences.kt:361-375` | `swipeEpisodeStartAction()` reads key `pref_episode_swipe_end_action` (default `ToggleSeen`); `swipeEpisodeEndAction()` reads `pref_episode_swipe_start_action` (default `ToggleBookmark`); chapters likewise (`pref_chapter_swipe_end_action` default `ToggleRead` for "start", `pref_chapter_swipe_start_action` default `ToggleBookmark` for "end"). Function names and key names are crossed. | Behaviour is internally consistent (the start-swipe setting always uses the "end" key), but anyone mapping keys by name gets the sides swapped. A backup from another build that fixed the names would swap the swipe sides. | Keep wire keys exactly.
