### A.1 Tap-zone geometry (applies to both navigation keys)

OBSERVED, from `READER/viewer/ViewerNavigation.kt` and `READER/viewer/navigation/*.kt`. Rectangles are fractions of the viewer view `(left, top, right, bottom)`.

- Hit test (`ViewerNavigation.getAction(pos)`): take `getRegions()` (the region list after applying the inversion mode), `find` the first region whose rect contains `(x, y)` (Android `RectF.contains`: `left <= x < right && top <= y < bottom`); return its `type`; if none matches return `MENU`. (A `constantMenuRegion = RectF(0, 0, 1, 0.05)` exists but both branches return `MENU`, so it has no effect.) `pos` is the touch point divided by the view width and height.
- Region types and their overlay colours (`NavigationRegion`, ARGB): `MENU` `0xCC95818D`, `PREV` `0xCCFF7733`, `NEXT` `0xCC84E296`, `LEFT` `0xCC7D1128`, `RIGHT` `0xCCA6CFD5`. Labels: `action_menu`, `nav_zone_prev` "Prev", `nav_zone_next` "Next", `nav_zone_left` "Left", `nav_zone_right` "Right".
- `DisabledNavigation`: empty region list, so every tap is `MENU`.
- `EdgeNavigation`, in list order: `(0, 0, 0.33, 1)` NEXT; `(0.33, 0.66, 0.66, 1)` PREV; `(0.66, 0, 1, 1)` NEXT. Everything else MENU (the centre column above y = 0.66).
- `KindlishNavigation`: `(0.33, 0.33, 1, 1)` NEXT; `(0, 0.33, 0.33, 1)` PREV. Top third is MENU.
- `LNavigation`: `(0, 0.33, 0.33, 0.66)` PREV; `(0, 0, 1, 0.33)` PREV; `(0.66, 0.33, 1, 0.66)` NEXT; `(0, 0.66, 1, 1)` NEXT. The centre cell `(0.33..0.66, 0.33..0.66)` is MENU.
- `RightAndLeftNavigation`: `(0, 0, 0.33, 1)` LEFT; `(0.66, 0, 1, 1)` RIGHT. The centre column is MENU.
- Inversion (`app/src/main/java/eu/kanade/tachiyomi/util/lang/RectFExtensions.kt:6-19`): mode HORIZONTAL -> `(1 - right, top, 1 - left, bottom)`; VERTICAL -> `(left, 1 - bottom, right, 1 - top)`; BOTH -> `(1 - right, 1 - bottom, 1 - left, 1 - top)`; NONE -> unchanged. The mode comes from `reader_tapping_inverted` (pager) and `reader_tapping_inverted_webtoon` (webtoon), `TappingInvertMode` = `NONE`, `HORIZONTAL`, `VERTICAL`, `BOTH` (`ReaderPreferences.kt:183-196`). Those keys live in another chunk but the geometry code is shared.
- Pager action dispatch (`PagerViewer.kt:113-119`): `MENU` -> `toggleMenu()`, `NEXT` -> `moveToNext()`, `PREV` -> `moveToPrevious()`, `RIGHT` -> `moveRight()`, `LEFT` -> `moveLeft()`. `moveRight` does nothing on the last page; otherwise, if `navigateToPan` and the page holder `canPanRight()`, it pans; else `pager.setCurrentItem(current + 1, usePageTransitions)`. `moveLeft` mirrors it with page 0 and `-1`.

Proposal: one module `reader::tap_zones` with `enum TapZones`, `fn regions(zones, default_for_viewer) -> &'static [(Rect, Region)]`, `fn invert(rect, mode) -> Rect` and `fn hit_test(...)`. Unit-test it with the centre cell of each layout and one point on each region boundary (the half-open interval matters at exactly 0.33 and 0.66).

### D.1 Automatic track selection (the consumer of language, whitelist, blacklist)

OBSERVED in `app/src/main/java/eu/kanade/tachiyomi/ui/player/utils/TrackSelect.kt:16-61`, called from `PLAYER/PlayerViewModel.kt:455-470` (`onFinishLoadingTracks`) once all tracks are loaded.

7. `filtered` = tracks (keeping their index) that do NOT contain any blacklisted word (case-insensitive substring of the name) and that `containsLang(chosenLocale)`.
