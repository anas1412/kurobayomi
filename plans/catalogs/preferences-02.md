## 0. Conventions used in every table

### 0.1 OBSERVED: how Aniyomi stores these keys

- Store column: every key in this file is **normal**. They live in the Android default `SharedPreferences` (`PreferenceManager.getDefaultSharedPreferences`) wrapped by `core/common/src/main/java/tachiyomi/core/common/preference/AndroidPreferenceStore.kt`. None carries the `__APP_STATE_` prefix (`Preference.appStateKey`, `core/common/src/main/java/tachiyomi/core/common/preference/Preference.kt:56`) or the `__PRIVATE_` prefix (`Preference.privateKey`). Consequence: all of them are included in the "app preferences" section of a backup (`app/src/main/java/eu/kanade/tachiyomi/data/backup/create/creators/PreferenceBackupCreator.kt:30` and `:62` filter only app-state keys, `:82` only private keys). A Kurobayomi backup importer therefore sees these key names verbatim (area:21-backup-format-and-create, area:22-backup-restore).
- Typed read: `AndroidPreference.get()` (`core/common/src/main/java/tachiyomi/core/common/preference/AndroidPreference.kt:28`) catches `ClassCastException`, logs `Invalid value for $key; deleting`, deletes the key and returns the default. Rust equivalent: a value of the wrong type in an imported backup or config file falls back to the default (log a warning), never an error.
- Backup value kinds are `Int`, `Long`, `Float`, `String`, `Boolean`, `Set<String>` (`PreferenceBackupCreator.kt:67-76`). Enums are stored as their `name` string (`getEnum`). Objects use a custom serializer string.
- Kotlin types in the tables use: `Boolean`, `Int`, `Long`, `String`, `Set<String>`.

### 0.2 Proposal: Rust configuration convention for this chunk

- One `Config` struct (serde) persisted as TOML at `$XDG_CONFIG_HOME/kurobayomi/config.toml` (fallback `~/.config/kurobayomi/config.toml`), written atomically (temp file + rename), loaded once at start and re-written on change by the settings UI. Field paths in the tables are written `section.field`. area:02-preferences-system owns the loader; this chunk only fixes field names, types and defaults.
- Unknown keys are preserved on re-write (so a newer config survives a downgrade). Missing keys take the default listed.
- Backup interop: the importer maps the Aniyomi key (first column) to the field and the exporter writes the same key with the same Kotlin type, so Aniyomi backups round-trip.
- Shared enum used below:
  - `TriState { Disabled, EnabledIs, EnabledNot }` mirrors `core/common/src/main/java/tachiyomi/core/common/preference/TriState.kt` (`DISABLED`, `ENABLED_IS`, `ENABLED_NOT`; `next()` cycles DISABLED -> ENABLED_IS -> ENABLED_NOT -> DISABLED). Filter semantics (`domain/src/main/java/tachiyomi/domain/entries/TriState.kt`): `applyFilter(DISABLED){p}` = true, `ENABLED_IS` = `p()`, `ENABLED_NOT` = `!p()`.

### 0.3 OBSERVED: the per-entry flag bit layouts that the `default_episode_*` and `default_season_*` keys feed

## 9. Findings summary for the plan authors

1. Seven library display toggles are shared between anime and manga libraries (section 1). Keep shared.
2. Anime "Set as default" for episodes writes into two keys shared with manga (`default_chapter_sort_by_ascending_or_descending`, `default_chapter_display_by_name_or_number`). Separate them in Rust (section 2).
3. Defect in `LibraryPreferences.setSeasonSettingsDefault` (`LibraryPreferences.kt:331`): the downloaded default is overwritten with the unseen flag and is lost when applied (section 3). Fix in Rust.
4. Defect in `AnimeLibraryUpdateJob.kt:296-300`: new episodes selected for download are never enqueued, unlike `MangaLibraryUpdateJob.kt:284` (section 4). Fix in Rust.
5. `download_slots` is a dead preference; concurrency is hard-coded to 3 sources and 2 pages (section 4). Do not port the setting.
6. `download_speed_limit` throttles only manga page images (section 4).
7. `TrustExtensionRepositoryMigration` has `version = 7f` and so never runs on current installs (section 6); stale `extension_repos` / `anime_extension_repos` sets can remain in preferences and in backups. The Rust importer must read them.
8. `ext_updates_count` and its anime twin are derived caches that leaked into backups; compute in memory.
9. `eh_enable_source_blacklist` is dead (commented out) and `episodeId` is an Intent extra, not a preference.
10. DoH is rebuilt only at client construction in Aniyomi; the user agent is actually read per request even though the UI claims a restart is needed.
