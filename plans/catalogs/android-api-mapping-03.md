## 2. Image loading pipeline (Coil)

Aniyomi loads every cover, background and reader webtoon strip through a Coil 3.1.0 `ImageLoader` built in `app/src/main/java/eu/kanade/tachiyomi/App.kt:182-212`. This section covers the nine Coil-related items together because they form one subsystem; the proposal at the end of the section is the Rust design that replaces all of them.

OBSERVED loader configuration (`App.kt:182-212`):

* Components in order: `OkHttpNetworkFetcherFactory(callFactoryLazy::value)` (Coil's generic HTTP fetcher), `TachiyomiImageDecoder.Factory()`, `BufferedSourceFetcher.Factory()`, `MangaCoverFetcher.MangaFactory`, `MangaCoverFetcher.MangaCoverFactory`, `AnimeImageFetcher.AnimeFactory`, `AnimeImageFetcher.AnimeCoverFactory`, then keyers `AnimeKeyer`, `MangaKeyer`, `AnimeCoverKeyer`, `MangaCoverKeyer`. The HTTP client is `Injekt.get<NetworkHelper>().client` (area:12-network-stack).
* `crossfade((300 * this@App.animatorDurationScale).toInt())` = 300 ms crossfade scaled by the system animation scale (`util/system/AnimationExtensions.kt`: `Settings.Global.ANIMATOR_DURATION_SCALE`, default 1.0).
* `allowRgb565(DeviceUtil.isLowRamDevice(this@App))`.
* `DebugLogger()` only when `networkPreferences.verboseLogging()` is true.
* `fetcherCoroutineContext(Dispatchers.IO.limitedParallelism(8))` (at most 8 concurrent fetches) and `decoderCoroutineContext(Dispatchers.IO.limitedParallelism(3))` (at most 3 concurrent decodes); the source comment says "Coil spawns a new thread for every image load by default".
* Library default (Coil 3, not in repo): memory cache is 25 percent of the app heap class; the default disk cache lives in `cacheDir/image_cache` with `maxSizePercent = 0.02` of the partition clamped to 10 MiB..250 MiB; filenames are the SHA-256 hex of the cache key.

OBSERVED cache keys (keyers in `app/src/main/java/eu/kanade/tachiyomi/data/coil/MangaCoverKeyer.kt` and `AnimeCoverKeyer.kt`): manga entity: `"manga;<id>;<coverLastModified>"` if it has a custom cover else `"manga;<thumbnailUrl>;<coverLastModified>"`; `MangaCover` value object: `"manga;<mangaId>;<lastModified>"` if the custom cover file exists else `"manga;<url>;<lastModified>"`. Anime adds the background variant: `useBackground && hasCustomBackground` -> `"anime;<id>;<backgroundLastModified>"`, `useBackground` -> `"anime;<backgroundUrl>;<backgroundLastModified>"`, then the cover forms with prefix `"anime;"`.

OBSERVED library cover storage (`data/cache/MangaCoverCache.kt:15-98`, `AnimeCoverCache.kt:21-22`, `AnimeBackgroundCache.kt:21-22`): library covers are plain files named `md5(thumbnailUrl)` (lowercase hex, `util/lang/Hash.kt`) in `getExternalFilesDir("covers")` (anime: `animecovers`, backgrounds: `animebackgrounds`), custom covers in `<dir>/custom/md5(id.toString())`. These directories are persistent app data (not cache); `deleteFromCache(manga, deleteCustomCover)` returns the number of files deleted.

### 2.1 DecodeUtils
* Aniyomi: `DecodeUtils.calculateInSampleSize(srcWidth, srcHeight, dstWidth, dstHeight, scale)` in `app/src/main/java/eu/kanade/tachiyomi/data/coil/TachiyomiImageDecoder.kt:35-41`. The result chooses the `sampleSize` handed to the native decoder (`decoder.decode(sampleSize = sampleSize)`, line 43) and sets `DecodeResult.isSampled = sampleSize > 1`. 1 file / 2 occ.
* Library default (Coil): `widthSample = highestOneBit(srcWidth / dstWidth).coerceAtLeast(1)`, same for height; `Scale.FILL` -> `min(widthSample, heightSample)`, `Scale.FIT` -> `max(...)`. Derived from `Utils.kt:21-26` (`Dimension.toPx`): an undefined dimension becomes `Int.MIN_VALUE` for `FILL` and `Int.MAX_VALUE` for `FIT`, so `src / dst` is 0 and the sample size is 1 (no downsampling).
* Replacement: own function `fn in_sample_size(src_w: u32, src_h: u32, dst_w: Option<u32>, dst_h: Option<u32>, fill: bool) -> u32` using `u32::checked_div` and `1u32 << (31 - x.leading_zeros())` for the highest power of two, `1` when the quotient is 0 or a dimension is `None`.
* Preserve: sample size is always a power of two and at least 1; undefined target size means decode at full size.
* Difficulty trivial. Risk: the Rust `image` crate cannot decode at a sampled size for JPEG without extra work; use `jpeg-decoder`/`zune-jpeg` scale-on-decode or decode full size and `resize` (acceptable for covers, which are already small).

### 2.2 Decoder
* Aniyomi: `class TachiyomiImageDecoder(resources: ImageSource, options: Options) : Decoder` (`TachiyomiImageDecoder.kt:20`). `decode()`: opens `tachiyomi.decoder.ImageDecoder.newInstance(stream, options.cropBorders, displayProfile)` (a native library, not in this repo), requires `width > 0 && height > 0` else `check` fails with "Failed to initialize decoder"; computes dst size from `options.size` (original -> source size); decodes bitmap (`"Failed to decode image"` on null); converts to a `HARDWARE` bitmap when `options.bitmapConfig == HARDWARE && ImageUtil.canUseHardwareBitmap(bitmap)`. `Factory.create` returns this decoder when `options.customDecoder` is true or the sniffed image type (`ImageUtil.findImageType`, which reads the first 32 bytes, `ImageUtil.kt:46-64,89-104`) is `AVIF`, `JXL` or `HEIF` (`isApplicable`, lines 72-80); otherwise Coil's default decoders (system `ImageDecoder`/`BitmapFactory`, GIF) are used. Companion `var displayProfile: ByteArray?` is filled from the reader's ICC profile preference (`ui/reader/ReaderActivity.kt:893-908`, `BasePreferences.displayProfile()` key `pref_display_profile_key`, default `""`). 1 file / 5 occ.
* Image types known to the app (`core/common/src/main/java/tachiyomi/core/common/util/system/ImageUtil.kt:106-114`): `AVIF("image/avif","avif")`, `GIF("image/gif","gif")`, `HEIF("image/heif","heif")`, `JPEG("image/jpeg","jpg")`, `JXL("image/jxl","jxl")`, `PNG("image/png","png")`, `WEBP("image/webp","webp")`; unknown extension falls back to `"jpg"` (`getExtensionFromMimeType`, line 67).
* Replacement: `trait ImageDecoder { fn probe(bytes: &[u8]) -> Option<ImageType>; fn decode(bytes: &[u8], opts: &DecodeOptions) -> Result<DecodedImage> }` with `DecodeOptions { target: Option<(u32,u32)>, scale: Fill|Fit, crop_borders: bool, icc_profile: Option<Vec<u8>> }`. P0 backend: `image` crate (JPEG, PNG, WebP, GIF). P1 backend: `libheif-rs` (HEIF/AVIF), `jxl-oxide` (JXL), or fall back to gdk-pixbuf loaders when installed. Magic-number sniffing of the first 32 bytes is kept (it is how the type is decided before decoding). ICC display profile: apply with the `lcms2` crate (`Transform` from the embedded/sRGB profile to the user profile) only when the preference is non-empty. Crop borders: the native decoder's algorithm is not in this repository, so Proposal: trim rows/columns from each edge while every pixel in the row/column is within a small tolerance of the edge colour (tolerance and the minimum remaining size are tunables in area:44-reader-viewers).
* Preserve: error strings "Failed to initialize decoder" / "Failed to decode image" map to page error state (retry button, `Page.State.ERROR`); decode of animated formats is not done here (see 4.8 Drawable and `ImageUtil.isAnimatedAndSupported`, GIF always, animated WebP/HEIF only on new Android; in Rust `gdk_pixbuf::PixbufAnimation` or the `image` crate `AnimationDecoder`).
* Difficulty moderate. Risks: AVIF/JXL decoders are optional C libraries; make them cargo features so the base build has no native dependency beyond GTK.

### 2.6 Fetcher
* Aniyomi: `MangaCoverFetcher` (`data/coil/MangaCoverFetcher.kt:48`) and `AnimeImageFetcher` (`AnimeImageFetcher.kt`, 367 lines, same structure plus the background variant at lines 308-324) fetch covers; `BufferedSourceFetcher` (`BufferedSourceFetcher.kt:12-36`) wraps an in-memory `BufferedSource` (used by the reader for page streams). 3 files / 18 occ.
* OBSERVED algorithm of `MangaCoverFetcher.fetch()` (lines 63-84; anime identical):
  1. If extra `USE_CUSTOM_COVER_KEY` is true and `coverCache.getCustomCoverFile(id)` exists -> serve that file.
  2. `url == null` -> `error("No cover specified")`.
  3. `getResourceType(url)` (lines 282-291): empty -> `null`; starts with `"http"` (ignore case) or `"Custom-"` -> URL; starts with `"/"` or `"file://"` -> File (`File(url.substringAfter("file://"))`); starts with `"content"` -> URI (Android SAF, opened with `UniFile.fromUri`); otherwise `null` -> `error("Invalid image")`.
  4. URL path (`httpLoader`, lines 100-170): if the manga is a library favourite (`isLibraryManga = data.favorite`) the target is `coverCache.getCoverFile(thumbnailUrl)`; if that file exists and `diskCachePolicy.readEnabled` -> serve it. Else open a Coil disk-cache snapshot under `diskCacheKey`; if present and the item is a favourite, copy the snapshot into the cover file and `remove(diskCacheKey)` (`moveSnapshotToCoverCache`, lines 204-218); if not a favourite serve the snapshot. Else go to the network: client is `sourceLazy.value?.client ?: callFactoryLazy.value` (the source's own OkHttp client, so source cookies/interceptors apply); request headers are the source's `headers`; `Cache-Control: no-store` when `networkCachePolicy.readEnabled` else `no-cache, only-if-cached` (which makes OkHttp answer 504); non-success and not 304 -> `IOException(response.message)`. On success a favourite writes the response body to the cover file (via `peekBody(Long.MAX_VALUE)`, delete-on-failure), otherwise writes to the Coil disk cache (`openEditor/commitAndOpenSnapshot`, abort on failure); if neither cache is usable the response body stream is served directly.
  5. Failures close the response body and snapshot before rethrowing.
* Replacement: `struct ImageService { http: reqwest::Client, covers: CoverStore, cache: DiskLru, sources: Arc<SourceRegistry> }` with `async fn load(&self, req: &ImageRequest) -> Result<ImageData>` implementing steps 1-5 exactly, with these Linux changes: `content://` URIs do not exist (drop the URI branch; `file://` and absolute paths remain); the `Custom-` prefix is kept and treated as an HTTP URL exactly as in `getResourceType` (nothing in this repo writes such a value; it can only come from a source or an old backup). Per-source HTTP client: `SourceRegistry::client_for(source_id)` returns the source's `reqwest::Client` (area:12-network-stack). Concurrency: `tokio::sync::Semaphore::new(8)` for fetch and a second `Semaphore::new(3)` for decode (matches `limitedParallelism(8)` and `(3)`). Request coalescing (same key in flight) is a Proposal: a `HashMap<String, Shared<Future>>` so a grid of 100 identical covers does one fetch.
* Preserve: library covers survive cache clearing (stored under `$XDG_DATA_HOME/kurobayomi/covers` and `animecovers`, `animebackgrounds`, `custom` subfolders, md5-hex file names, see section header); a non-library cover is cache-only; adding to the library promotes the cached snapshot to the permanent cover file; custom cover wins unless the request opts out.
* Difficulty moderate. Risk: atomic writes; always write to `<name>.tmp` then `rename` so a crash never leaves a half file that a later `exists()` check would trust.

### 2.7 DiskCache
* Aniyomi: `coil3.disk.DiskCache` is used through `imageLoader.diskCache` in the two cover fetchers (`MangaCoverFetcher.kt:204-280`): `openSnapshot(key)` (read), `openEditor(key)` + `fileSystem.write(editor.data)` + `commitAndOpenSnapshot()` / `abort()` (write), `remove(key)`, `snapshot.data` (a path), `Snapshot.close()`. Input: decoded RGBA8 image (full size). Output: `enum PageBackground { Solid(Rgba), Gradient([Rgba;4]) /* top to bottom, evenly spaced stops at 0, 1/3, 2/3, 1 */ }`. `WHITE = 0xFFFFFFFF`.   2. `top = 5`, `bot = h - 5`, `left = (w * 0.0275) as i32`, `right = w - left`, `mid_x = w / 2`, `mid_y = h / 2`, `offset_x = (w * 0.01) as i32`, `left_off = left - offset_x`, `right_off = right + offset_x`. Sample `TL=(left,top)`, `TR=(right,top)`, `ML=(left,mid_y)`, `MR=(right,mid_y)`, `TC=(mid_x,top)`, `BL=(left,bot)`, `BC=(mid_x,bot)`, `BR=(right,bot)`.
  3. `dark_bg = (dark(TL) && (dark(BL) || dark(BR) || dark(TR) || dark(ML) || dark(TC))) || (dark(TR) && (dark(BR) || dark(BL) || dark(MR) || dark(TC)))`.
  4. Ring test: `ring = [TL, TC, TR, BR, BC, BL]`; if for every index i `!is_white(ring[i]) && is_close(ring[i], ring[(i+1) % 6])` -> `Solid(TL)`.
  5. If more than 2 of `[TL, TR, BL, BR]` are white -> `dark_bg = false`.
  6. `black = first of TL, TR, BL, BR that is dark, else WHITE`.
  7. Column scan: counters `overall_white = overall_black = top_black_streak = top_white_streak = bot_black_streak = bot_white_streak = 0`; for `x` in `[left, right, left_off, right_off]` (in that order): `white_streak_n = white_n = black_streak_n = black_n = 0`, `black_streak = white_streak = false`, `not_offset = (x == left || x == right)`; for `(index, y)` over `y = 0, step, 2*step, ... < h` with `step = h / 25` (integer; `h >= 50` guarantees `step >= 2`): `pixel = img[x, y]`, `pixel_off = img[x + (x < w/2 ? -offset_x : +offset_x), y]`. If `is_white(pixel)`: `white_streak_n += 1; white_n += 1; if not_offset { overall_white += 1 }; if white_streak_n > 14 { white_streak = true }; if white_streak_n > 6 && white_streak_n >= index - 1 { top_white_streak = white_streak_n }`. Else: `white_streak_n = 0; if is_dark(pixel) && is_dark(pixel_off) { black_n += 1; if not_offset { overall_black += 1 }; black_streak_n += 1; if black_streak_n >= 14 { black_streak = true }; continue }`. After the if/else (reached for white pixels and for non-white non-dark pixels): `if black_streak_n > 6 && black_streak_n >= index - 1 { top_black_streak = black_streak_n }; black_streak_n = 0`. After the loop: `if black_streak_n > 6 { bot_black_streak = black_streak_n } else if white_streak_n > 6 { bot_white_streak = white_streak_n }`. Then, first matching branch: (a) `black_n > 22`: if `x == right || x == right_off` then `black = dark(TR) ? TR : dark(BR) ? BR : black`; `dark_bg = true; overall_white = 0; break out of all columns`. (b) `black_streak`: `dark_bg = true`; same right-side `black` update; if `black_n > 18 { overall_white = 0; break }`. (c) `white_streak || white_n > 22`: `dark_bg = false`.
  8. `top_is_black_streak = top_black_streak > top_white_streak`; `bottom_is_black_streak = bot_black_streak > bot_white_streak`; `if overall_white > 9 && overall_white > overall_black { dark_bg = false }`; `if top_is_black_streak && bottom_is_black_streak { dark_bg = true }`.
  9. If the window is landscape (`configuration.orientation == ORIENTATION_LANDSCAPE`): `Solid(dark_bg ? black : WHITE)`. On desktop define landscape as `window_width > window_height`.
  10. Else: `bot_white_corners = white(BL) && white(BR)`, `top_white_corners = white(TL) && white(TR)`, `top_dark_corners = dark(TL) && dark(TR)`, `bot_dark_corners = dark(BL) && dark(BR)`, `top_off_dark = dark(img[left_off, top]) && dark(img[right_off, top])`, `bot_off_dark = dark(img[left_off, bot]) && dark(img[right_off, bot])`. First matching: `dark_bg && bot_white_corners` -> `Gradient([black, black, WHITE, WHITE])`; `dark_bg && top_white_corners` -> `Gradient([WHITE, WHITE, black, black])`; `dark_bg` -> `Solid(black)`; `top_is_black_streak || (top_dark_corners && top_off_dark && (dark(TC) || overall_black > 9))` -> `Gradient([black, black, WHITE, WHITE])`; `bottom_is_black_streak || (bot_dark_corners && bot_off_dark && (dark(BC) || overall_black > 9))` -> `Gradient([WHITE, WHITE, black, black])`; otherwise `Solid(WHITE)`.
  Render with a `gtk::Widget` background via CSS `background: linear-gradient(to bottom, c0 0%, c1 33.33%, c2 66.66%, c3 100%)` or a `GtkSnapshot::append_linear_gradient`. Unit-test with synthetic images (all white, all black, black top band, dark side gutters).
* Preserve: all constants above; the "automatic background" is reader theme value 3 of `pref_reader_theme_key` (0 white, 1 black = default, 2 gray, 3 automatic, `ReaderPreferences.kt:57`, `ReaderActivity.kt:841-850`, `PagerConfig.kt:56`), it exists only for the pager viewers (the webtoon viewer does not call `chooseBackground`), and animated images skip it.
