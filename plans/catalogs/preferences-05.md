## 0. How the Aniyomi preference store behaves (needed to read the rows)

OBSERVED (`core/common/src/main/java/tachiyomi/core/common/preference/AndroidPreferenceStore.kt`, `core/common/src/main/java/tachiyomi/core/common/preference/AndroidPreference.kt`, `core/common/src/main/java/tachiyomi/core/common/preference/Preference.kt`, `core/common/src/main/java/tachiyomi/core/common/preference/PreferenceStore.kt`, `core/common/src/main/java/tachiyomi/core/common/preference/TriState.kt`):

- One flat key namespace backed by Android `PreferenceManager.getDefaultSharedPreferences(context)`. There are no per-feature files. Typed accessors: `getString`, `getLong`, `getInt`, `getFloat`, `getBoolean`, `getStringSet`, `getObject(key, default, serializer, deserializer)`, and the extension `getEnum<T>`.
- "Store" column values used in this document. `normal` means the key is stored as written. `private` means the stored key would carry the prefix `__PRIVATE_` (`Preference.privateKey`, excluded from backups unless the user consents). `app-state` means the stored key would carry the prefix `__APP_STATE_` (`Preference.appStateKey`, never exported in backups: `app/src/main/java/eu/kanade/tachiyomi/data/backup/create/creators/PreferenceBackupCreator.kt` filters with `Preference.isAppState`). All 46 items in this chunk are `normal`; none is wrapped in `privateKey` or `appStateKey`. (`pref_downloaded_only` and `incognito_mode` in `app/src/main/java/eu/kanade/domain/base/BasePreferences.kt:17,21` are the app-state examples, and belong to other chunks.)
- `getEnum` serializes with `Enum.name` (a string) and deserializes with `enumValueOf`; an unknown name yields the default value (`core/common/src/main/java/tachiyomi/core/common/preference/PreferenceStore.kt`, the `getEnum` extension). `AndroidPreference.Object.read` reads with `preferences.getString(key, null)` and catches every `Exception`, returning the default. So an enum key that was stored as an Int (see `pref_filter_downloaded_key` below) silently reads as the default.
- For primitive types a stored value of the wrong type throws `ClassCastException`, which `AndroidPreference.get()` catches: it logs "Invalid value for $key; deleting", deletes the key and returns the default.
- `changes()` is a `Flow` that emits the current value first (`onStart { emit("ignition") }`) and again on every write of that key. The Rust equivalent is a `tokio::sync::watch` per field (Proposal in section 1).
- Backups export every non-app-state key by key name with its raw type: Int, Long, Float, String, Boolean, StringSet (`app/src/main/java/eu/kanade/tachiyomi/data/backup/create/creators/PreferenceBackupCreator.kt`, `toBackupPreferences`). Enum-valued keys travel as `StringPreferenceValue` holding the enum name. For Kurobayomi's Aniyomi-backup import (area:22-backup-restore) every row below therefore gives the exact legacy key, wire type and accepted values.
- Migrations that touch keys in this chunk are listed in `app/src/main/java/mihon/core/migration/migrations/Migrations.kt`: `MigrateToTriStateMigration()` (version 52f), `MigrateTriStateMigration()` (version 99f), `EnumsMigration()` (version 123f). They are covered in section 6.

## 1. Proposed Rust configuration layout for these keys

Proposal: `Config` is a serde struct with one nested struct per area. Names below are the field paths used in the rows. Enum values keep the Aniyomi `name` strings so that an Aniyomi backup value maps by identity (`#[serde(rename_all = "SCREAMING_SNAKE_CASE")]` only where the Kotlin names are in that case, otherwise the exact Kotlin names through a per-variant `#[serde(rename = "<Kotlin name>")]`).

```rust
#[derive(Serialize, Deserialize, Clone, Copy, PartialEq, Eq, Default)]
#[serde(rename_all = "SCREAMING_SNAKE_CASE")]
pub enum TriState { #[default] Disabled, EnabledIs, EnabledNot }   // "DISABLED" | "ENABLED_IS" | "ENABLED_NOT"

impl TriState {
    pub fn next(self) -> Self { match self { Self::Disabled => Self::EnabledIs, Self::EnabledIs => Self::EnabledNot, Self::EnabledNot => Self::Disabled } }
    /// domain/src/main/java/tachiyomi/domain/entries/TriState.kt:5  applyFilter
    pub fn apply(self, predicate: impl FnOnce() -> bool) -> bool {
        match self { Self::Disabled => true, Self::EnabledIs => predicate(), Self::EnabledNot => !predicate() }
    }
}

#[derive(Serialize, Deserialize, Clone, Copy, PartialEq, Eq, Default)]
pub enum EpisodeSwipeAction { #[default] ToggleSeen, ToggleBookmark, ToggleFillermark, Download, Disabled }

#[derive(Serialize, Deserialize, Clone, Copy, PartialEq, Eq, Default)]
#[repr(u8)]
pub enum ImageScaleType { #[default] FitScreen = 1, Stretch = 2, FitWidth = 3, FitHeight = 4, OriginalSize = 5, SmartFit = 6 }
```

Unknown or invalid stored values must fall back to the field default, as `getEnum` does. A deserialization failure of one field must not discard the whole config file (use `#[serde(default)]` on every struct and a lenient per-field fallback).

### 2.2 OBSERVED details and Proposals per key

**`pref_dual_page_split` and `pref_dual_page_split_webtoon` (split wide pages).**

OBSERVED:
- "Wide" is `ImageUtil.isWideImage`: `options.outWidth > options.outHeight`, strict (`core/common/src/main/java/tachiyomi/core/common/util/system/ImageUtil.kt:121-124`). Dimensions come from a bounds-only decode, so the image is not fully decoded for the test.
- The processing order for any page, paged (`app/src/main/java/eu/kanade/tachiyomi/ui/reader/viewer/pager/PagerPageHolder.kt:178-199`): (1) if `dualPageRotateToFit` then rotate (and return; split is never reached); (2) if not `dualPageSplit` return the source unchanged; (3) if the page is an `InsertPage` (the synthetic second half) return `splitInHalf`; (4) if not wide return unchanged; (5) otherwise call `onPageSplit(page)` and return `splitInHalf`.
- `splitInHalf` (`core/common/src/main/java/tachiyomi/core/common/util/system/ImageUtil.kt:129-148`): decode the bitmap, `singlePage = Rect(0,0,width/2,height)`, output bitmap `width/2` by `height`, and the source rectangle is `Rect(width - width/2, 0, width, height)` for `Side.RIGHT` or `Rect(0, 0, width/2, height)` for `Side.LEFT`. With an odd width the centre column is dropped. The result is re-encoded as JPEG quality 100.
- Which half the original page keeps (paged, `app/src/main/java/eu/kanade/tachiyomi/ui/reader/viewer/pager/PagerPageHolder.kt:221-236`): `L2RPagerViewer` and original page gets `LEFT`, its `InsertPage` gets `RIGHT`; every other viewer (`R2LPagerViewer` and `VerticalPagerViewer`) the original gets `RIGHT`, its `InsertPage` gets `LEFT`. If the sibling pref `pref_dual_page_invert` (chunk 4) is true the side is swapped.
- Insert position (`app/src/main/java/eu/kanade/tachiyomi/ui/reader/viewer/pager/PagerViewerAdapter.kt:162-194`): `onPageSplit` returns immediately if the page is not a `ReaderPage`; if the split page belongs to a chapter other than the current one the new `InsertPage` is parked in `preprocessed[newPage.index]` and inserted later; otherwise `placeAtIndex = currentIndex + 1` for `L2RPagerViewer` and `VerticalPagerViewer`, `currentIndex` for the right-to-left viewer; it does nothing when the target slot or (for right-to-left) the previous slot already holds an `InsertPage`, to avoid an endless insert cycle; then `items.add(placeAtIndex, newPage)` and `notifyDataSetChanged()`.
- Turning `pref_dual_page_split` off at runtime calls `cleanupPageSplit()` which removes every `InsertPage` from the adapter (`app/src/main/java/eu/kanade/tachiyomi/ui/reader/viewer/pager/PagerViewer.kt:132-136`, `app/src/main/java/eu/kanade/tachiyomi/ui/reader/viewer/pager/PagerViewerAdapter.kt:196-200`); turning it on or off also fires `imagePropertyChangedListener` which refreshes the adapter (`app/src/main/java/eu/kanade/tachiyomi/ui/reader/viewer/pager/PagerConfig.kt:86-95`).
- Webtoon variant (`app/src/main/java/eu/kanade/tachiyomi/ui/reader/viewer/webtoon/WebtoonPageHolder.kt:222-227`): when wide, `ImageUtil.splitAndMerge(source, upperSide)` produces one image of size `(width/2) x (height*2)`; the upper part is the right half (`upperSide = RIGHT`) or the left half (`upperSide = LEFT` when `pref_dual_page_invert_webtoon` is true); the lower part is the other half (`core/common/src/main/java/tachiyomi/core/common/util/system/ImageUtil.kt:166-193`). No pages are inserted.
- Settings screen coupling: switching the split switch (either direction) writes `false` to the matching rotate preference (`app/src/main/java/eu/kanade/presentation/more/settings/screen/SettingsReaderScreen.kt:275-282` paged, `370-377` webtoon: `onValueChanged = { rotateToFitPref.set(false); true }`). Switching rotate writes `false` to the matching split preference (`app/src/main/java/eu/kanade/presentation/more/settings/screen/SettingsReaderScreen.kt:289-295` paged, `384-391` webtoon). The "Invert split page placement" switch is enabled only while split is on (`enabled = dualPageSplit`); the "Flip orientation" switch only while rotate is on (`enabled = rotateToFit`).
- Upstream defect in the in-reader quick sheet (paged group, `app/src/main/java/eu/kanade/presentation/reader/settings/ReadingModePage.kt:119-130`): the checkbox labelled "Split wide pages" is bound to `dualPageInvertPaged()` (key `pref_dual_page_invert`), and the checkbox labelled "Invert split page placement" (shown while split is on) is bound to `dualPageRotateToFitInvert()` (key `pref_dual_page_rotate_invert`). The webtoon group of the same sheet (`app/src/main/java/eu/kanade/presentation/reader/settings/ReadingModePage.kt:179-190`) is wired correctly. The quick sheet also does not clear the opposite flag.

Proposal:
- Implement the split as a per-page pre-processing step in the page pipeline (area:44-reader-viewers), with the order rotate, then split, exactly as above. Use the `image` crate's `GenericImageView::view(x, y, w, h).to_image()` for the half crops with the same integer rule (`left = 0..w/2`, `right = (w - w/2)..w`) and keep the result as raw RGBA; do not re-encode to JPEG (the Kotlin re-encode is lossy and only exists because the downstream view takes a stream).
- Reimplement the insert-page model so that the second half is a virtual page with the same `index` as the original (the Kotlin viewer detects a split pair by "both pages have the same number", `app/src/main/java/eu/kanade/tachiyomi/ui/reader/viewer/pager/PagerViewer.kt:182-185`).
- Bind the quick sheet controls to the correct keys (do not copy the upstream defect) and apply the same mutual exclusion as the Settings screen in both places.
- Decision on mutual exclusion: when a config file is loaded with both split and rotate true, honour rotate (as the code path does) and show split as visually off-but-stored; do not rewrite the file.

**`pref_dual_page_rotate`, `pref_dual_page_rotate_webtoon`, `pref_dual_page_rotate_invert`, `pref_dual_page_rotate_invert_webtoon` (rotate wide pages to fit).**

OBSERVED:
- `rotateDualPage` (`app/src/main/java/eu/kanade/tachiyomi/ui/reader/viewer/pager/PagerPageHolder.kt:205-216`, `app/src/main/java/eu/kanade/tachiyomi/ui/reader/viewer/webtoon/WebtoonPageHolder.kt:230-240`): if the page is wide, `ImageUtil.rotateImage(source, if (dualPageRotateToFitInvert) -90f else 90f)`; otherwise the source is returned unchanged. `rotateImage` builds an Android `Matrix().postRotate(degrees)`, creates the rotated bitmap, and JPEG-compresses at quality 100 (`core/common/src/main/java/tachiyomi/core/common/util/system/ImageUtil.kt:150-163`). `postRotate(90)` is a clockwise rotation in Android's y-down coordinates.
- The rotate preference is read by `PagerConfig` for the paged viewer (`app/src/main/java/eu/kanade/tachiyomi/ui/reader/viewer/pager/PagerConfig.kt:98-107`) and by `WebtoonConfig` with the `_webtoon` keys (`app/src/main/java/eu/kanade/tachiyomi/ui/reader/viewer/webtoon/WebtoonConfig.kt:68-79`). Changing it fires `imagePropertyChangedListener`, which refreshes the viewer.

Proposal:
- Rotation is a pure transform: `image::imageops::rotate90` for `false` and `rotate270` for `true` (width and height swap). Do the rotation after decode and before tiling so that all zoom/scale-type maths operates on the rotated size.
- The two "invert" keys keep their Aniyomi names in the backup importer only; in the Rust config they are `reader.dual_page_rotate_invert_paged` and `reader.dual_page_rotate_invert_webtoon`.

**`pref_enable_double_tap_zoom_webtoon`.**

Each result becomes `TimeStamp(start=startTime, end=endTime, name="Opening"|"Ending"|"Recap"|"Mixed-op", type=Opening|Ending|Recap|MixedOp)`. `getMalIdFromAL`: POST `https://graphql.anilist.co` with JSON `{"query": "query{ Media(id:$id){idMal} }"}` (whitespace as written), parses with `substringAfter("idMal\":").substringBefore("}").toLongOrNull()` and returns `0` on null or on exception.
- Defect: the `SkipType` enum has no constant for `mixed-ed` although the request asks for that type; the app Json (`app/src/main/java/eu/kanade/tachiyomi/di/AppModule.kt:174-177`: `ignoreUnknownKeys = true`, `explicitNulls = false`, no `coerceInputValues`) would throw on an unknown enum value, the `catch (_: Exception)` swallows it, and the whole response is lost.

Proposal:
- Port the whole group to `player.skip_intro.{enabled, auto_skip, netflix_style, aniskip_enabled, disable_aniskip_on_chapters, waiting_time_secs}`; read the values live from the watch channel instead of once at construction (cheap in Rust).
- Run the countdown off the same 1 Hz integer `time-pos` observation (observe `time-pos` as `MPV_FORMAT_INT64`), to keep the Aniyomi feel (the countdown runs faster at 2x speed and freezes while paused).
- AniSkip client: `reqwest` GET with the identical URL and a 10 s timeout, never on the UI thread; tolerant parsing: define `SkipType` with `#[serde(other)] Unknown` plus a `mixed-ed` variant mapped to `ChapterType::Ending` named "Mixed-ed", ignore unknown results individually so one bad entry never discards the rest; same `idMal` GraphQL lookup but parsed with serde JSON (`data.Media.idMal` as `Option<u64>`); consult all trackers' tracks in order instead of only the first.
- Dedupe: cache the AniSkip result per `(mal_id, episode_number, duration)` in memory for the session.

**`pref_gesture_volume_brightness` and `pref_gesture_horizontal_seek`.**

OBSERVED (`app/src/main/java/eu/kanade/tachiyomi/ui/player/controls/GestureHandler.kt`):

Do not touch the monitor backlight.

- Store filters as nested tables `library.filters.anime` and `library.filters.manga` so the Rust `LibraryFilter` struct can be passed straight into the SQL/in-memory filter (area:37-ui-library). The tri-state evaluation is the `TriState::apply` method in section 1. Counters (`unseenCount`, `unreadCount`, `bookmarkCount`, `seenCount`, `readCount`) come from the library query (area:05-data-repos-entries-items).
- Tracked filter: show only trackers that support the media kind (manga-only: Komga, Kavita, Suwayomi, MangaUpdates; anime-only: Simkl, Jellyfin; both: MyAnimeList, AniList, Kitsu, Shikimori, Bangumi) in the matching library; Aniyomi shows every logged-in tracker in both (observed above), which is only noise. Stored map entries for trackers that are not logged in are preserved but ignored.
- "Downloaded only" global mode (the app-state key `pref_downloaded_only`, another chunk) forces `Downloaded` to IS in the evaluation and disables its row; it must not rewrite the stored filter value.
- Aniyomi-backup import: accept the three `TriState` names; ignore Int values for these keys (see section 6, where an Int was written by an old migration).

Further notes for section 6:
- Observed defect in `app/src/main/java/mihon/core/migration/migrations/MigrateToTriStateMigration.kt:21-35`: it writes with `putInt` under the v2 keys (`filterDownloadedManga().key()`, `filterUnread().key()`, `filterCompletedManga().key()`), but those keys are read through `getEnum`, which uses `getString`. So the migrated value was never honoured. Consequence for the importer: a backup may contain `pref_filter_library_downloaded_v2`, `pref_filter_library_unread_v2` or `pref_filter_library_completed_v2` as an `IntPreferenceValue`; treat any non-string value of a `TriState` key as `DISABLED`.
