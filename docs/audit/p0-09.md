What is solid: the pure logic and the new pages. The anime entry page (`src/entry_core/anime/route.rs`) and the Browse tab (`src/browse/`) are real, model-driven, and heavily tested. The flag codecs, filter and sort engines, missing-episode separators, selection model, settings window, list widget (`gio::ListStore` behind a `ListView`), sources grouping, listing/paging, favourite flows and filter sheet all exist with tests and are called from the window. The gaps are at the edges, where the new pages meet old code or a service that was never installed.

Main findings:

1. **The old mockup pages are still reachable, which is why "the redesign didn't reach everything".** `screens::open_entry(title, anime)` (`src/screens.rs:83`) resolves a title over LOCAL library rows only (`src/local_flow_anime/open.rs:67`, `src/local_flow/open.rs:19`). Any other title falls to `entry::entry()` (`src/entry.rs:85`), the static page with "Studio", "Ongoing", "Source A (EN)" and a throwaway seeded database. Callers that pass only a title: the Library grid for every non-local entry (`src/library/mount.rs:318-329`), the Updates cover tap (`src/updates/updates_screen.rs:400`) and the History screen (`src/updates/history_screen.rs:225,277`). So in the real library a remote anime or manga opens the mockup. The real pages open by id from Browse, Migrate, Search, Upcoming, notifications and deep links. Fix: pass the id through (`entry_core::anime::route::open(id)`, `entry_core::route::open(id)`) and delete the anime branch of `entry::entry`.
2. **Global search still shows placeholders from the Library.** `open_global_search` (`src/library/mount.rs:168`) calls `ui::open("global_search")` with nothing parked. `browse::search_screen::body` (`src/browse/search_screen.rs:366-385`) then returns `None`, and `entry::global_search` (`src/entry.rs:657`) builds "Source A/B/C", a progress bar fixed at 0.6, `title_n(n)` covers and "No results found". The same fallbacks in `entry.rs` are `sources` (`:508`), `extensions` (`:536`, "Extension A"), `migrate_sources` (`:585`), `migrate_entries` (`:707`) and `tracker_search`. They show whenever the page is opened without a parked route.
3. **The Tracking sheet opened from the anime and manga pages is a mockup.** `route.rs:1064,1119` and `entry_core/route.rs:689,1155` call `ui::open("tracking_sheet")`, which `screens::body` sends to `entry::tracking()` (`src/entry.rs:723`): fake "AniList / MyAnimeList / Kitsu", "12 / 24", "8.0", `title_n(1)`. The real tracking helpers in `src/entry_core/tracking/` are not mounted here. (Not a P0 task of this shard; it limits T-39a-026.)
4. **No anime download queue is ever installed.** `download_backend::install_queue` (`src/entry_core/anime/download_backend.rs:20`) has no caller, so `AnimeDownloads::can_enqueue()` is false on every page. The Download menu and the Download and Delete rows of the bottom bar never show, the refresh auto-download can never queue, and `EpisodeItem`/`derive_download` (queued download beats disk copy, progress) is unused. Only the "downloaded on disk" set reaches the rows.
5. **The Extensions tab cannot install, update or uninstall.** `HostBackend` (`src/browse/mount.rs:197`, used at `:564`) answers install with the Error step, uninstall with nothing, and refresh with `Ok(())`. The state machine (`browse/installs.rs`) is well tested but ends in Error every time.
6. **Several services are stubbed behind the new pages.** `RemoteAnimeBackend` uses `NoCoverFiles` (`src/entry_core/anime/remote.rs:132,194`), so the refresh cover/background rules and the cover delete on library removal do nothing; it does not override `play_external` (`runner.rs:95`, default `false`) so the external player is never used; the manga browse favourite store gets a `|_| 0` cover clearer (`src/browse/browse_screen.rs:212`).
7. **Episode and manga default-flag keys still collide** (`kuro-domain/src/entries/defaults.rs:22`, `kuro-prefs/src/library.rs:108-114`): the task asks for separate Kurobayomi keys, the code keeps the upstream shared keys (area 07 Q3 said preserve for v1).
8. **Smaller wiring gaps:** the sidebar never calls `browse::mount::reselect()` (T-40a-001); the manga browse page hard-codes `configurable: false` (`browse_screen.rs:84`) so Settings never shows for a manga source; the registry readiness gate is fed a constant `true` (`mount.rs:480`, `browse_screen.rs:71`); Global search is in the header overflow menu, not a header button (`shell.rs:354`); `from_source` is always `false` on the anime page (`route.rs:125`), so the description starts collapsed on a small layout even when opened from Browse; the anime source line uses the always-suffixed `display_name`, not the single-language rule (`remote.rs:119`).
9. **Plan deviations that are recorded in code and not counted as gaps:** browse preferences live in the shared `config.toml` `[sources]` table, not `browse.toml` (`src/browse/prefs.rs:1-4`); landscape columns use the 720 px width rule of area 41 (D14); the Help action is omitted because no help page exists (T-14a-047); `UserMessage` has 12 keys, with the other 16 rows of behaviour section 19 owned by other modules (`src/entry_core/message.rs:1-15`).
