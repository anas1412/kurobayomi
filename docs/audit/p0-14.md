What is solid: the settings shell and its back handling, the extension store and repo pages (reducer, backend, GTK page, DB, live list), the preference widgets as used by the typed settings pages, the highlight flash, onboarding, the language validator, the custom-button table and seed, and the theme engine (scheme resolution, AMOLED, portal dark detection, CSS generation, token tests). The module layout differs from the plan: the plan's `src/settings/*` is `src/pref_model/*` and `src/settings_ui/*`, `src/prefs` is `crates/kuro-prefs`, `src/player/*` is `crates/kuro-player` plus `crates/kuro-domain/src/custom_buttons`.

Main findings (these are why "the redesign did not reach everything"):

1. **The App theme picker is not on the Appearance page.** `spec/settings.json` has "App theme" as a `chips` item and `spec_convert.rs:51,157` skips `chips`, so the row never appears. Both card strips (`pref_model/widgets/app_theme.rs:198 strip` and `theme/picker.rs theme_cards`) have no caller. The only place a user can pick one of the 18 schemes is the onboarding wizard, as a drop-down, and it only stores the value (`shell/onboarding.rs:231-237`). T-47ba-041, T-47ba-042.
2. **Theme mode on Appearance is a list dialog, not the three-segment control, and it does not re-render the palette.** `settings_ui/appearance.rs:63 apply_theme_mode` sets `gtk-application-prefer-dark-theme` from the portal value (SYSTEM is forced to the portal bool, not reset). `theme::apply::set_settings` has no caller except the unused `theme/picker.rs:142`, so for a non-System scheme the `kb-dark` window class and palette stay at the startup mode until restart. Pure black is a hard-coded `#000000` provider at USER priority (`appearance.rs:204`), not the theme's AMOLED overrides.
3. **The More page is still the spec mockup.** `screens.rs:373 more()` builds from `spec/settings.json`; `pref_model::more::page` (logo, moved-tab row, live queue subtitle) has no caller. The moved-tab row is dropped whatever `bottom_rail_nav_style` says (`screens.rs:381`), so with "Move Browse to More" the More tab has no Browse row. The queue subtitle is the constant `Stopped` (`screens.rs:386`); `QueueCombiner` has no caller. The Download queue page itself is an empty-state placeholder (`screens.rs:430`, "No download manager runs in the app yet").
4. **The mockup widgets are still the renderer for every spec dialog, sheet and generic page.** `ui.rs:332 item_row` still builds `gtk::DropDown`, a `MenuButton` popover multi-select, the plain slider and its own switch (gaps G-01, G-02, G-03 are open). The typed widgets (list dialog, multi-select dialog, slider with pill, switch) are used only by the settings pages built through `pref_model::page::body`.
5. **The live player ignores almost all player settings.** `src/player_view/mod.rs:75` builds `PlayerPrefs::default()` and reads only `remember_decoder`, remembered volume and `open_detached` from the store. The progress threshold is the constant 0.85 (`player_view/store.rs:12`), `preserve watching position` is passed as `false`, and the hosters, gestures, double-tap, seeking, display, subtitle, audio, decoder, `mpv.conf`, `input.conf` and `mpv_scripts` settings are stored but never read. The gesture dispatch (`settings_ui/player/gestures.rs:95`), the Lua bridge (`kuro-player/src/bridge.rs:154`), the custom-button runtime and the favourite-button state have no caller from the live player. `player_scripts::start` is called only from the placeholder player (`player.rs:58`, `screens::build("player")`, fake 23:40 duration), whose result is only logged.
6. **The settings row metrics differ from the plan on purpose.** `docs/design/other-tabs.md` records 48 px rows, 12/8 px padding, 24 px between groups, a `heading` group label, no logo and an info row with the icon beside the text. The plan says 56/16/16, 12 px, a small group label, a 64 px logo and the icon above. I count the redesign as the decision and mark those bullets met (T-47ba-006, -007, -045) or not applicable (T-47ba-012, the logo). The plan's CSS file `resources/style.css` and the `.pref-title` class do not exist; the CSS is in `pref_model/style.rs`.
7. **The extension store page misses its deep-link entry and the repo add path has gaps.** `StoresPage::open_deep_link` (`stores_page.rs:186`) has no caller. An empty signing fingerprint in `repo.json` is accepted (`extension_repo/mod.rs:73`), and the failed-add toast says "Unknown error" instead of "Could not add the repo".
8. **Dead mockup arms remain in `src/settings.rs`** (`cards`, `editor`, `code_editor`, `text_dump` for worker info, `licenses`). They are unreachable because `screens::body` asks `settings_ui::handles` first. The one live leftover is `settings_open_source_library_license`, a static "Apache License Version 2.0" text (`settings.rs:25`).
9. **Components of area 49a have no caller.** Badge, progress ring, list group header, section card, the settings-row family and the dialog layout in `theme/components/*` are used by nothing outside `theme/` (the app builds badges, headers and dialogs in `screens.rs`, `ui.rs` and `pref_model/widgets/dialog.rs`).
10. **Preference storage is TOML, not the SQLite kv table** the T-48a-001 text names. This follows plan 02's own design (`plans/02-preferences-system/p1-rust-design.md`: `config.toml` and `state.toml`, in-memory values, debounced save), so I count it as met.
