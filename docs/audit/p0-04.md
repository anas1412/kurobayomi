## Summary

1. Area 16a is in good shape. The anime source API, models, hoster and video pipeline, URL and id rules, and HTTP base are implemented in `crates/kuro-source` and `crates/kuro-source-http` with many tests, and the video path is reachable: entry page -> `src/entry_core/anime/route.rs:1572` -> `src/player_view/source.rs` -> `best_video`. The sources that exist in the app (KickAssAnime, recipe sources) run through it.
2. The layout differs from the plan text (`src/source/...`). The crates layout in `plans/CRATE-MAP.md` replaced it, so I did not count that as a gap. What is a gap: `src/` still uses `reqwest` directly in many places (`src/ext_host.rs:326`, `src/browse/builtin.rs:25`, `src/pref_model/net.rs`, and more), which breaks the T-16a-001 rule.
3. Area 17a is mostly library code. `SourceRegistry`, `SourceSystem`, stub registration, the index fallback chain, `SourceIdentity` and the typed errors in `crates/kuro-domain/src/source/` are tested but nothing in `src/` calls them (no hit for `SourceRegistry`, `SourceSystem` or `register_stub` outside the domain crate). The app instead has a `SourceDirectory` seam (`src/browse/directory.rs`) fed by built-in sources and recipe sources (`src/browse/builtin.rs`, `src/recipe_sources.rs`), and `src/browse/anime/directory.rs:4` says "the app has no anime source registry yet". Consequence: sources from installed extensions never become runnable.
4. The source-ready gate is not real. `src/source_gate.rs` `when_sources_ready` has no call site, and every Browse screen builds its readiness with `watch::channel(true)` (for example `src/browse/mount.rs:480`, `src/browse/browse_screen.rs:71`, `src/browse/search_screen.rs:183`), so the spinner never shows and nothing waits on a registry.
5. Two things in 17a are duplicated, and the tested copy is not the wired copy. The enabled list: tested `compute_enabled_sources` (`crates/kuro-domain/src/app/source.rs:62`) is unused, the screen uses `source_list` (`src/browse/sources.rs:71`). The language groups: tested `group_by_language` (`crates/kuro-domain/src/source/languages.rs:22`) is unused, the screen uses `sources_filter_groups` (`src/browse/lang_pages.rs:44`).
6. Area 18a is the weakest. The full manga design (manifest, `.kuroext` reader, ed25519 verify, install queue, startup loader, wasmtime host) exists in `crates/kuro-source-wasm`, but the app does not depend on it. The only reference is `crates/kuro-extensions/src/instantiate.rs`, whose `scan_and_instantiate` is never called, and which drops the instantiated sources (`Ok(_)` at line 26). The app instead:
   - scans the old folder layout with `kuro_extensions::loader::scan_into(.., &BTreeMap::new(), ..)` (`src/ext_host.rs:284`). The empty trust map means every manga package is Untrusted, none ever shows as Installed.
   - uses the area-19 anime stack (`kuro_extensions::anime`) for the anime tab. That stack refuses non-anime manifests (`crates/kuro-extensions/src/anime/package/manifest.rs`, rule 2 `kind == "anime"`), so it cannot serve manga.
7. The Browse extension screens cannot install, uninstall or update anything: `HostBackend` in `src/browse/mount.rs:197-208` reports `InstallStep::Error` for install, does nothing for uninstall and refresh. No manga index (`index.min.json`) is fetched anywhere, so the manga Available list is always empty.
8. Bug found in passing: the Trust button on an Untrusted extension (`src/browse/mount.rs:544-549`) writes the bare package name into `trusted_extensions`. The trust rule reads `<pkg>:<versionCode>:<digest>` entries (`crates/kuro-domain/src/extension/trust.rs:94`, `crates/kuro-extensions/src/anime/trust.rs:45`), so this never trusts anything, and no reload follows. `ExtensionState::trust` (`crates/kuro-extensions/src/anime/manager.rs:288`) exists but has no caller.
9. Smaller plan-versus-code deviations are listed per task (Header equals Select in filters, no `LibVersion`, 30 s repo timeout against 15 s, cover cache cleaners not wired in the anime refresh, test E-C6 relaxed from 50 ms to 1 s).

Verdict rule used: LIB_ONLY when the code meets the acceptance bullets but nothing in the window calls it. PARTIAL when an acceptance bullet is not met, even if the code is also unwired (the row says so). MISSING when no implementation of the task exists for the manga plan (an anime-only sibling is named in the row where one exists).
