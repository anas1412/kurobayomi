### Area 44a: the reader viewers are real and reachable

The pager and the webtoon engines are built and wired. `src/reader/screen.rs:1308` calls `make_viewer(kind, ctx)` through `EngineViewer` (`src/reader/viewers/adapter.rs`), and the reader is opened from the entry screens (`src/entry_core/route.rs:706`, `src/reader/launch.rs`), from history and from deep links. Each piece has a pure controller with unit tests (`pager/controller.rs`, `webtoon/controller.rs`, `nav.rs`, `keys.rs`, `gap.rs`, `items.rs`, `settings.rs`, `webtoon/zoom.rs`, `webtoon/layout.rs`) and a GTK engine (`engine.rs`). The golden files named in the plan exist in `tests/fixtures/reader/golden/` (nav_*, pager_*, webtoon_*, quick_scale, zoom_pinch). The three gaps:

1. T-44a-026: the pager hides the menu when the page slider moves the page. `PagerController::set_slider_moving` (`pager/controller.rs:~157`) is only called by tests. Nothing in `src/reader/screen.rs` (`move_viewer`, line 1389) sets the flag, so `on_settled` always emits `HideMenu`.
2. T-44a-062: a loading page row shows the text "Chapter <database id> page <n>" above the spinner (`engine.rs:151-153`, used as the status label in `holder.rs` `Image::build`). A page with no loader shows the same text instead of staying blank (E-40; the test `a_network_page_of_a_chapter_with_no_loader_stays_a_plain_label` asserts the label). This is leftover scaffolding text.
3. T-44a-045: the minimum-scale math is `f64`; the task asks for `f32` parity (`src/reader/page_zoom.rs:94`). Low impact.

### Area 45a: the real player is a thin shell over the library

The crate `crates/kuro-player` holds nearly everything the plan asked for, with about 27,000 lines and many tests. The app window uses only a small part of it. The real player is `src/player_view/` (GLArea plus libmpv, a play button, a seek bar, a volume slider, a fullscreen button, a track menu, progress saving). It is opened for local episodes (`src/local_flow_anime/open.rs:49`) and for episodes of online sources (`src/player_view/source.rs:22`).

What the app takes from `kuro_player` (checked with `rg "kuro_player::" src`): `mpv::MpvHandle`, `options::{PlayerPrefs, startup_settings}`, `session::prepare_mpv_dir`, `shortcuts::action_for`, `keys::Modifiers`, `observer::MpvEvent`, `seekbar_model`, `remember`, `load::{start_command_ms, http_header_fields}`, `tracks`, `seek`, `progress`. It does not construct `Session`, `PlayerState`, the bridge, the observer table, the key map, the error reporter, the episode switcher or the lifecycle gate. Those are tested in the crate and called by nothing in `src/`.

Findings that explain most gaps:

1. The player ignores the player preferences. `src/player_view/mod.rs:75-77` builds `PlayerPrefs { data_dir, ..PlayerPrefs::default() }` and only copies the decoder opt-in (lines 80-83). The stored values of `pref_gpu_next`, debanding, `use_yuv420p`, verbose logging, `pref_player_speed`, all subtitle and audio options, the five video filters and the screenshot folder are never read. The startup table is built from defaults (`screenshot-directory` is an empty path). Affects T-45a-003, 004, 005, 030, 031, 033.
2. The Advanced settings page stores `mpv.conf` and `input.conf` text in the preference store ("the player writes the files at each start", `src/settings_ui/player/advanced.rs:3`), but `prepare_mpv_dir(&prefs)` (`mod.rs:85`) gets the default empty `AdvancedPrefs`, so every player start truncates both files and the user text is never applied (T-45a-026).
3. Two settings that the Controls page offers have no effect: `pref_progress_preference` and `pref_preserve_watching_position` (`src/settings_ui/player/controls.rs:87-88`). `src/player_view/store.rs:12` hard-codes 0.85 and `store.rs:17-21` passes `false` for the preserve flag (T-45a-012, 064).
4. Nothing observes mpv properties (`observe_all` has no caller outside tests), so no speed, aspect, chapter, track, cache or error events reach the window. mpv events are read by polling `drain_events` every 250 ms (`mod.rs:~478`). A playback error is only a `tracing::warn!` (`mod.rs:482`); there is no toast (T-45a-009).
5. There is no episode switching, no autoplay at end of file, no previous or next button, no single-instance rule, no speed or aspect control, no chapter list, no skip button in `src/player_view/`. The crate has the logic (`episodes.rs`, `playlist.rs`, `window.rs`, `aspect.rs`, `speed.rs`).
6. Keys are not forwarded to mpv. `src/player_view/mod.rs` maps only the `shortcuts::Action` subset: pause, seek, volume, fullscreen, Escape. `keys.rs` (key names, repeat swallowing, `keydown`/`keyup`) is unused, so mpv's `input.conf` bindings never fire.
7. The mockup is still the fallback player. `src/screens.rs:94-98` (`open_media`) calls `crate::player::player(title, unit)` whenever the episode is neither a local episode nor an online-source episode (also the `screens.rs:46` demo route). `src/player.rs` is the old placeholder: a `gtk::Box` marked "placeholder surface", a fixed 1420 s duration, a "00:00 • Opening" chapter button, a "Skip Opening" pill, a fake speed cycle, no mpv. This is a place where the redesign did not reach.
8. Downloaded (non-local) anime episodes are not played from their file: `entry_core/anime/route.rs` `open_player` goes to `open_source_episode` (online resolve) and never asks the download index (T-45a-068).
