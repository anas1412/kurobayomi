# P0 audit 07: areas 34a, 35a, 36a

Read-only audit by reading code. Cargo was not run; "test exists" means the test name was found in the source, not that it passes (test not run). A task is DONE only if the code path is reachable from the app window (`src/main.rs` -> `build_window`, `ext_host::start` -> `browse::builtin::start`, the library, entry, browse and settings screens).

## Summary

60 P0 tasks: DONE 33, LIB_ONLY 4, PARTIAL 22, MISSING 0, NOT_APPLICABLE 1.

What matters most:

1. **The cover pipeline is real, but the cover widget is not the redesigned one.** `ImageService` (fetch, caches, decode, memory cache) is created in `src/browse/builtin.rs:258` and installed into `CoverView` (`src/entry_core/cover_view.rs`), which the library cards, browse lists, entry header and updates/history use. But `CoverView` is a plain `gtk::Frame` with a symbolic icon placeholder. It does not use `CoverRatio`, the `#1F888888` placeholder class, or the `cover_error` image (T-34a-052). `ui::cover()` in `src/ui.rs:288` is still the grey frame with the comment "until there is an image loader". Two anime pages still call it, so those covers never load: `src/entry_core/anime/related_view.rs:18`, `src/entry_core/anime/season_grid.rs:103` and `:131`.
2. **Opening an entry from a deep link, notification or desktop action is still a mockup lookup.** `src/open_link.rs:35` calls `screens::open_entry(&screens::title_n(id), anime)`, and `title_n` is the string `"Title <id>"`. It only finds a real entry if its title is literally `Title 5`; otherwise it pushes the mockup entry page (`src/screens.rs:91`). `shell::entry_route` (T-36a-060), which would route by id, has no caller. `screens::build("reader" | "player")` also fall back to `"Title 1"` samples (`src/screens.rs:40`, `:46`).
3. **Onboarding step 2 stores the folder in the wrong format.** `src/shell/onboarding.rs:277` writes the raw path into `__APP_STATE_storage_dir`. The rest of the app stores the base64 of the path bytes through `StorageManager::set_base` (`crates/kuro-domain/src/storage/manager.rs:84`) and reads it with `settings_ui::storage::decode` (`src/settings_ui/storage.rs:40`). A folder chosen in the wizard is therefore not seen by the storage page, backups or downloads, and the folder tree is not created.
4. **Several shell components are built and tested but nothing calls them** (`#[allow(dead_code)]` in `src/shell/mod.rs`): `appbar`, `search`, `tabbed`, `empty`, `date_text`, `warning`, `webview`, `entry_route`, and the `Navigator` in `nav`. Screens use their own header, search and empty-state code instead (`ui::page`, `browse::header_bar`, `browse::look::empty_state`, `updates::dates`).
5. **Area 34 has parallel copies.** The reader has its own page cache (`src/reader/cache.rs`) and decoder (`src/reader/page_decode.rs`), the entry screens have their own chapter number format (`src/entry_core/numfmt.rs`, which gives `0.0005 -> "0.001"`, not the golden `"0"`) and error texts (`src/entry_core/errors.rs`). The matching `kuro-images` modules (`chapter_cache`, `buffered`, `format`, `exception`, `invalidate::prep_update_cover`) have no caller in `src/`.
6. **Cover invalidation is only half wired.** Removing from the library via the library selection deletes covers (`src/library/mount.rs:273`); removing via the heart on the entry page calls a default `remove_cover` that returns false and deletes nothing (`src/entry_core/backend.rs:59`, `src/entry_core/anime/runner.rs:55`). Source refresh paths never delete the old cover file or protect a custom cover (`kuro-domain` `refresh_update`, `src/entry_core/anime/remote.rs:134` `NoCoverFiles`).
7. **Navigation chrome deviates from the plan.** `NavStyle` only decides which tab hides the bottom bar; the sidebar and bottom bar always list all five spec entries. Reselecting the current tab opens Settings from the sidebar but not from the bottom bar. Page transitions are 300 ms SlideLeft/SlideRight (`src/shell/transitions.rs`), not 250 ms SlideLeftRight.
