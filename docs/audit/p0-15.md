Main findings:

1. **The theme and icon redesign lives in `src/theme/` but most of it is not called.** Startup does reach `theme::startup` (`src/main.rs:210`, `src/theme/mod.rs:118`): icon bundle, stored scheme, base sheet, palette provider, portal follower. Everything that a screen would call is unused: `theme::empty_state` (kaomoji faces), `theme::loading`, `theme::cover::placeholder`, `theme::picker` (mode row, theme cards, AMOLED switch), `theme::AppTheme`, every `Icon` consumer (`anime_library_icon`, `caret_icon`, `reading_mode_image`, `download_indicator`, `notification_icon`, `set_toggle_state`), the `.kb-selected`, `.kb-active` and `.kb-secondary-item` classes, and `widget_names::name_reader_pager`. Screens keep their own stock-icon widgets (`browse::look::empty_state`, `ui::cover`, `entry_core/list_view.rs:64`, the sidebar icons from `spec/app.json`). This is the cause of "the redesign did not reach everything".
2. **There is no app-theme picker after onboarding.** The Appearance page is the spec tree merged with typed rows (`src/settings_ui/route.rs:155`, `src/settings_ui/merge.rs`). The spec's "App theme" row is a `chips` item the converter skips and no typed row replaces it, so only "Theme mode" and "Pure black dark mode" show. The only theme choice a user can make is the onboarding dropdown (`src/shell/onboarding.rs:227`), which writes `pref_app_theme` but does not apply it until the next start, and it cannot select the GTK theme or Tokyo Night.
3. **Three theme-mode and AMOLED paths disagree** (also found in shard 01). The page's mode list calls `settings_ui::appearance::apply_theme_mode` (`src/settings_ui/appearance.rs:63`), which only sets the GTK dark preference. It does not update `theme::apply`'s stored settings, so the palette dark flag, the `kb-dark` and `kb-amoled` window classes and the tint rules stay at the start-up values, and the next portal change re-applies the old mode. Pure black is a separate fourth provider at USER priority (`appearance.rs:204-223`) rather than the token AMOLED of `resolve::apply_amoled`.
4. **Two stored names for the GTK theme.** `theme/prefs.rs` writes `SYSTEM` on first run. `theme::AppTheme::GtkTheme` (dead) stores `GTK_THEME`. `kuro_prefs::ui::UiPrefs::app_theme` has default `DEFAULT` (`crates/kuro-prefs/src/ui.rs:143`) and cannot read `SYSTEM`. `spec/settings.json` and `spec/app.json` still say Dynamic and Default (T-49b-006 asked for them to match the decision).
5. **Utility functions exist twice, the tested copy is unused.** Next-unread (`src/selection.rs` vs `src/library/actions.rs:322`), dedupe (`kuro_core::collections` vs `src/reader/chapters.rs:59`), downloaded-only filter (four copies: `src/entry_core/downloaded.rs`, `src/shell/downloaded.rs`, `src/library_update/downloaded.rs`, `src/entry_core/anime/playlist_filter.rs`; the live reader uses a lookup built in `src/reader/launch.rs`), language names (`src/locale.rs` vs `src/browse/names.rs`), file-name sanitiser (`kuro_platform::filename` vs `kuro_core::text::build_valid_filename`; they disagree on reserved names: `_CON` vs `CON_`), player root and reader root (`src/shell/player_root.rs`, `src/shell/reader_root.rs` vs `src/player_view/mod.rs:231`, `src/reader/screen.rs:715`). The live copies work; the plan's named ones are dead code.
6. **i18n catalogue is complete but the app is not fully on it.** 1,063 `MsgKey` uses in 142 files, but `src/screens.rs`, `src/ui.rs`, `src/entry.rs`, `src/live.rs` and `src/settings_ui/appearance.rs` use none; sidebar and page titles come from the English spec JSON (`src/main.rs:470`). With `LANG=de_DE.UTF-8` those stay English (T-51a-043).
7. **A mock player and a mock entry page remain reachable.** `screens::open_media` falls back to `src/player.rs` ("Previous episode" buttons, a fake player) when no local episode or source episode is found (`src/screens.rs:94-98`), and `screens::open_entry` falls back to `entry::entry` (`src/screens.rs:83-91`). The spec screen id `player` always builds the mock (`src/screens.rs:46`). The Global search placeholder noted in shard 01 (`entry::global_search`, `src/entry.rs:657`) is the same class of problem.
8. **Platform-boundary check currently fails on the repo's own audit reports.** `scripts/check-platform-boundary.sh` does not exclude `docs/audit/`, and `p0-01.md` and `p0-05.md` contain the forbidden words, so CI would go red. This report avoids them. Fix: add `--glob '!docs/**'` to the script.
9. **Task-list drift in 54a.** The root `Cargo.toml` lists members one by one and there is no `xtask` crate, although `docs/drop-decisions.md` and `plans/NOT-PORTING.md` point at `cargo xtask lint` and `cargo xtask dist`. gtk4 is built with `v4_14` but CONTRIBUTING.md says `v4_16` (README says 4.14, CI comment says 4.14). The release profile has no `strip`.
