# P0 audit, shard 10: plan areas 41a, 41b (browse anime) and 42a (history, tab shell, formatting)

Read-only audit by reading code and test names. Cargo was not run, so no test result below is a pass or fail; "tests exist" means a test with that name is in the tree. 62 P0 tasks (41a 20, 41b 24, 42a 18).

## Summary

Counts: DONE 36, LIB_ONLY 2, PARTIAL 24, MISSING 0, NOT_APPLICABLE 0.

Most of the anime Browse and History code is real and wired to the window. The gaps are a handful of stubs that sit under otherwise finished screens:

1. The WebView page is still the mockup. `src/entry.rs:797-809` draws a fixed "https://example.org/" and a "Web content" placeholder ("no web engine linked"). `entry_core::handoff::open_webview` parks a request that only tests read (`take_webview` has no production caller). So "Open in WebView" (browse overflow, error state, extension row globe, extension details) opens a sample page. Affects T-41a-005, 011, 41b-023, 044.
2. The Extensions tab backend does nothing. `HostBackend` in `src/browse/mount.rs:197-208`: install reports Error, uninstall is empty, refresh returns Ok at once. The real install, uninstall and refresh live in `kuro-extensions` (`anime/service.rs`, `anime/install/mod.rs`) and nothing in `src/` calls them. Affects T-41a-011, 012, 013, 015. The Trust button also writes the bare package name into `__APP_STATE_trusted_extensions` (`src/browse/mount.rs:545`), but `TrustStore` only accepts `<pkg>:<versionCode>:<digest>` and the set is only read at scan time, so trusting changes nothing. `has_installed` (mount.rs:254) reads the MANGA registry and is used for the anime tab too.
3. Help is dropped from every browse error state and overflow (`kuro_local::ux::LOCAL_HELP_URL = None`, decision T-14a-047, a P2 task that overrides these P0 acceptance lines). Affects T-41a-005, 007, 41b-018, 023, 044. The local source error state then shows only Retry.
4. Adding a favourite from Browse does no side effects. `production_env` (`src/browse/anime/browse_screen.rs:120-149`) builds `AnimeStore::new` with no `.with_add_effects(...)` (only `src/updates/history_add.rs:129` attaches it), so no default episode flags and no enhanced tracker binding; the cover and background clearers are `|_| 0`, so Remove deletes no files (T-41b-020).
5. Browse error text is the raw `Display` of `SourceError` ("HTTP error 503"), not the formatted "HTTP 503, check website in WebView". `kuro_source::messages::source_error_message` is tested and has no caller in `src/` (`browse_error_text` is test-only). T-41b-042.
6. No loading rows while paging. The Browse listing shows a spinner only when the list is empty (`src/browse/content.rs`); the prepend/append 16 dp spinner rows of T-41a-006 and T-41b-018 do not exist.
7. History opens things by title, not id (`src/updates/history_screen.rs:236-243`, `open_unit` 331-338 -> `screens::open_entry` / `open_media`). Title lookup only finds LOCAL-source entries (`local_flow*::..._with_title` use `favorites_by_source(LOCAL_SOURCE_ID)`). A cover click on a history row of a non-local entry pushes the sample entry page (`entry::entry(title, anime)`); resuming a non-local anime episode opens the placeholder player (`src/player.rs:53-70`, "placeholder surface", fixed 1420 s). Manga resume resolves by title in `reader::launch::find_ids` and works for any source. `pref_always_use_external_player` is read and only logged; no external launcher. T-42a-014, 016.
8. The area 42 pure modules sit in the GUI crate (`src/updates/*`, `#![allow(dead_code)]`) and not in `kuro-domain`; `kuro-domain` has no `format` or `stats` module, depends on `rusqlite`, and several of the constants of T-42a-001 are missing or duplicated. Several helpers have no caller: `updates::format::relative_date`, `updates::nav::{sidebar_index, from_more}`, `list::item_key`/`RowKey`, `shell::tabbed` (area 36 twin of T-42a-007).
9. Global search placeholders (the user's report): `screens::body("global_search")` (`src/screens.rs:26`) uses `browse::search_screen::body`, which returns `None` unless a route, intent or entry-page search was parked, and then falls back to `entry::global_search` (`src/entry.rs:657-701`: "Source A/B/C", "Title 1..8", fixed 0.6 progress). All current openers park first, so the sample page shows only without app data or for a bare `ui::open("global_search")`. Global search itself is outside this shard (area 41c).

Notes on how verdicts were judged: a "typed route" replaces the Kotlin sentinel strings (decision Q-BR-1), so `Listing::from_nav_arg` having no app caller was not held against T-41b-011. Where the redesign doc (`docs/design/other-tabs.md`) records a layout change (header row instead of a `ui/tabbed.rs` title bar, 48x72 history cover) the layout was not held against the task.
