# P0 audit, shard 06: plan areas 26a (library update jobs) and 28a (AniList tracker)

Read-only audit by reading code and test names. Cargo was not run, so no test result below is a pass or fail; 'tests exist' means a test with that name is in the tree. 74 P0 tasks.

## Summary

Counts: DONE 30, LIB_ONLY 33, PARTIAL 11, MISSING 0, NOT_APPLICABLE 0.

Findings that explain most gaps:

1. The library update pass cannot reach any source from the app window (area 26). `src/misc/runner.rs:55-79` builds the pass with `NothingInstalled`, a registry that returns no source for any id. The refresh button, the schedule and `--library-update` all run the real pass (lock, queue, restrictions, progress notice, counters, error log), but every entry ends as "Source not found", so the sync, the new-item counters, the summary and the download hand-off never run from the window. The entry pages already have working lookups (`browse::directory::current().manga_source`, `entry_core/anime/remote.rs` AnimeSourceLookup, `browse::builtin`), so the fix is one registry in `src/misc/runner.rs`. Also `Fetched.details` is fetched when "Automatically refresh metadata" is on and then thrown away (`src/library_update/sync.rs:144`).
2. Missing pieces of area 26 that are not source related: no `library_job_run` table (the lock is an in-process mutex, T-26a-129); the live progress feed has no subscriber (`progress::header_bar` is never called, T-26a-130); the summary is a toast instead of a desktop notification (T-26a-032); `src/library_update/reading.rs` is dead duplicate code (T-26a-061, 064, the feature itself works through `kuro_domain::library::active::continue_target`).
3. The AniList crate is thorough but the app does not use it (area 28). `crates/kuro-track/src/tracker/anilist/` has the DTOs, queries, score and status rules, login, search, bind, update, refresh and delete with about 115 tests. From the window only two things are reachable: the Tracking settings row (opens the browser, logout dialog) and the tracker being registered.
4. The login cannot finish: the `kurobayomi://` / `aniyomi://anilist-auth#...` link reaches `src/shell/launch.rs:61`, which only raises the window. `tracker_host::on_redirect` (the real handler) has no caller.
5. The entry page tracking UI is still the mockup: `ui::open("tracking_sheet")` (`src/entry_core/route.rs:689,1155`, `src/entry_core/anime/route.rs:1064,1119`) draws `src/entry.rs:723-762` with fixed rows and the spec dialogs; `tracker_search` (`src/entry.rs:764-790`) shows four fake results. The status, score and search logic in `src/entry_core/tracking/*` and `kuro-track` has no widget on top of it.
6. Reading or watching never updates a tracker: `src/reader/launch.rs:204` passes `track_update: None`.

No task of this shard is NOT_APPLICABLE: the drop records in `plans/NOT-PORTING.md` for areas 26a and 28a are all P3 tasks.
