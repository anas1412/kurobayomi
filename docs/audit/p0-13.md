# P0 audit 13: areas 45b, 46a, 46b, 47a

Read-only audit by reading code. Cargo was not run: "test exists" means the test name was found in the source, "test not run". A task is DONE only if the code path is reachable from the app window. `kp/` below means `crates/kuro-player/src/`.

## Summary

95 P0 tasks: DONE 21, LIB_ONLY 50, PARTIAL 23, MISSING 1, NOT_APPLICABLE 0.

By area: 45b (player core) 39 tasks, 46a (controls UI) 22, 46b (sheets and panels) 17, 47a (settings screens) 17. Areas 45b, 46a and 46b are almost all LIB_ONLY: the `kuro-player` crate is a large, well-tested set of pure models, but the player window does not use them. The 47a settings screens are mostly real and live.

What matters most:

1. **The live player is a small page, not the designed player.** `src/player_view/mod.rs` has a GL area, a header (Back, title, Detach, a Tracks popover), one bar (play, a `gtk::Scale`, one time label, volume, fullscreen) and key shortcuts. From `kuro_player` it uses only about a dozen items (`mpv`, `observer::MpvEvent`, `options::startup_settings`, `seekbar_model` labels, `tracks`, `progress`, `seek` flags, `load`, `remember`, `keys`/`shortcuts`). Nothing builds the `Store`/`PlayerState`, `playlist`, `loader`/`hosters` session, `session`, `overlay`, gestures, sheets, speed, aspect, chapters, skip-intro, volume boost, brightness or the session file. That is why the 46a/46b tasks come out LIB_ONLY.
2. **The old mockup player is still what users reach from History, Updates and Library resume.** `screens::open_media` (`src/screens.rs:95-98`) plays only local episodes through `player_view`; every other episode opens `src/player.rs`, which has a constant duration of 1420, a fixed "00:00 - Opening" label and static spec sheets. Callers: `src/library/mount.rs:345`, `src/updates/history_screen.rs:377`, `src/updates/open_route.rs:47`, and the entry page itself when the source is not in `live_anime_sources` (`src/entry_core/anime/route.rs:1575`). Only the entry page's Play for a live online source goes through `open_source_episode` (`route.rs:1572`). This is the clearest "redesign did not reach it" case.
3. **Player settings do not reach mpv.** `src/player_view/mod.rs:75-85` builds `PlayerPrefs` from defaults and sets only `data_dir` and the remembered decoder. Subtitle style, audio language, gpu-next, debanding, hardware-decoding switch, filters, `mpv.conf`, speed and aspect set in Settings > Player are stored but never applied. Also `pref_preserve_watching_position` and `pref_progress_preference` are ignored (`src/player_view/store.rs`).
4. **Two parallel implementations of the same logic.** Hoster loading, best-video choice and video resolve exist in `kuro-source` (`anime/loader.rs`, `anime/hoster.rs`, live) and again in `kp/hosters.rs` and `kp/loader.rs` (no caller). Same for the type definitions (`kp/types.rs` against `kuro_source::anime`). The player preference catalogue is also kept twice (`kp/player_prefs.rs` and `kuro-prefs`); a script check found equal defaults for all 104 keys today.
5. **Offline and download paths are missing in the live player.** A downloaded episode of an online source is re-resolved over the network (no download check in `player_view`), and there are no previous/next, auto-next, skip-intro, chapters, speed, aspect, hosters or quality sheet.
6. **Settings (47a) gaps are small.** The 11-row main list still shows Android subtitles (`spec/settings.json`) because `settings_ui/menu.rs` is dead code; `SearchableSettings` has two implementors only; global search ignores the two hide-in-library switches; the Pure black row is not live on the Appearance page; disabled rows are greyed, not collapsed. Onboarding stores the storage folder in a different format from the Storage page (raw path against base64), so the chosen folder is not recognised there.

Verdict rules used: DONE = implemented, tests by name, reachable from the window. LIB_ONLY = implemented and tested in a crate or module, no caller in `src/`. PARTIAL = part of the acceptance is live (or the crate part itself misses bullets). MISSING = nothing found. Where the plan's paths (`src/player/*.rs`) differ from the code, the crate location is what was judged.
