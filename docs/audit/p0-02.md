## Cross-cutting findings

**G1. Library, History and Updates open entries by title, and non-local entries open the mock page.** `screens::open_entry(title, anime)` (src/screens.rs:83-92) resolves the title only over local-source rows (`local_flow::open::entry_for_title`, `local_flow_anime::anime_id_for_title`). Anything else pushes `entry::entry(title, anime)` (src/entry.rs:85), which builds an `EntryModel` on a temporary database seeded with fake rows (src/entry_model.rs:93-122, "Source A (EN)", "Studio"). Callers: Library nav (src/library/mount.rs:322-330), History (src/updates/history_screen.rs:225,277), Updates cover tap (src/updates/updates_screen.rs:400). The continue button and unit taps go through `screens::open_media`, which falls back to `reader::launch::page_for` / `player::player` mock pages for non-local items. Only Browse, global search, notifications, upcoming and deep links open the real pages by id (`entry_core::route::open(id)`). Fix: pass the entry id through Library/History/Updates and call `entry_core::route::open` / `entry_core::anime::route::open`. Affects T-06a-080, T-07a-040, T-08a-033.

**G2. Global search opened from the Library is the placeholder page.** src/library/mount.rs:168 `open_global_search` calls `ui::open("global_search")` with nothing parked. `search_screen::body(false)` returns `None` when there is no intent, parked route or entry hand-off (src/browse/search_screen.rs:375-390), so `screens::body` falls back to `entry::global_search` (src/entry.rs:657) with "Source A/B/C", "Title 1..8" cards, a fixed 60% progress bar and "No results found" on the third source. The code then types the query into the first search entry of that mock page. Fix: park `BrowseRoute::GlobalSearch { kind, source_id: None, query }` (as `deep_link_page::open_search` does through `pending::open`) before opening, and make the sidebar/Browse entry do the same. This is the placeholder the user reported. Affects T-08a-016.

**G3. The Library tab never refreshes from the database.** Tabs are built once at startup (src/main.rs:437-448). `LibraryView` reloads on preference changes (src/library/view/mod.rs:480-497), local-folder scans and its own bulk actions (src/library/mount.rs:139, 373, 429). Nothing subscribes to the manga/anime tables, and no caller of `library::mount::refresh` exists for reads, favourites added in Browse or the entry page, or finished library updates. History, Updates and Categories do watch (`bind_watch`). Judged by reading; not run. Fix: subscribe with `Db::subscribe_tables(LIBRARY_DEPS, ..)` through `bind_watch` and call `submit`. Affects T-08a-032, T-08a-033, T-07a-022.

**G4. The library update pass has no sources.** src/misc/runner.rs:73 `NothingInstalled` is the `SourceRegistry` of both the library update runner and the backup host (src/backup_run.rs:44); every entry ends "source not installed". The sync code (T-10a-008/009) is only reached from the entry details pages and migration. Area 26 owns the fix; it limits what T-10a-007/008/009 deliver.

**G5. Domain pieces built twice, the app uses the copy.** Paging: kuro_source `RemotePager`, kuro_domain `PageCursor`, browse `Pager`. History recording: kuro-data `HistoryRecorder`, kuro-domain `ReadTimer`/`WatchTicker`, reader timer. Enabled sources: `compute_enabled_sources` vs src/browse/sources.rs. Add-target: `resolve_add_target` vs `entry_core::favorite::route_add`. Chapter flags: domain setters vs `entry_core::flags`. Migrations: kuro_core vs kuro_prefs (empty list). Download policy: kuro-domain vs kuro-downloads. Each pair should be reduced to one.

**G6. Concrete user-visible bugs found.** Category delete dialog shows a raw `%s` (T-08a-033). The per-category sort switch resets only manga categories (T-08a-012, Q9). Browse listing errors show "HTTP error 404" style text instead of the formatted messages (T-06a-043). The storage tree is not created at startup (T-09a-048). Nothing writes next-episode airing data (T-10a-004). Stub sources are never written (T-06a-041).
